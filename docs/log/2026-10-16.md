### 2026-10-16 —— CI 红修：抽 kBootstrap 的正则把 JVM 栈打穿（换线性扫描）

**红在哪**：`ci.yml` run `38902403070` 的 `:app:testDebugUnitTest` —— `BridgeDistPackagingEntryTest`
三例里「dist env 缺席」那条炸 `java.lang.StackOverflowError`，栈里一千多层**全是**
`java.util.regex.Pattern$Loop` / `GroupHead` / `GroupTail` / `BranchConn`（report XML 里连测试
自己的帧都被挤出栈顶）。不是新写的 Kotlin 有毛病，是**共用的取件夹具**：
`app/src/test/kotlin/com/autoscript/e2e/E2EFixtures.kt` 的 `extractBootstrap` 拿
`Regex("""constexpr const char kBootstrap\[\]\s*=\s*((?:"(?:[^"\\]|\\.)*"\s*)+)""")`
从 main.cpp **现抽**引导串（"抽而不抄"是 §12.4 交付轨的单一事实源纪律，这条不动）。

**病**：那串正则的嵌套量词让 JVM 正则引擎**按字符递归**，栈深随字面量块长度线性涨。本机对拍
（JDK 17，跑编译出来的 class，与 CI 同一台引擎）：`HEAD~3` 那份 main.cpp 块长 **1132 字符、
冷调用也抽得动**；今天加了第 4 段装配（`installStdinIdleWatch` 那段）涨到 **1233 字符 → 冷调用
`StackOverflowError`**。**"三例只红一例"也坐实了**（同一个 1MB 栈线程里连测）：
**第 1 次（冷、解释执行）炸 → 第 2/3 次（热、`Pattern$Loop` 已 JIT 编译，帧小得多）过**，
先吃 300 层栈仍过、吃到 1200 层又炸 —— 也就是说 `:app` 那一整个测试 JVM 里**只有第一个调用
`repoBootstrap()` 的用例会红**（堆栈深度在"够"与"不够"之间，胜负由解释/编译形态翻转）。
这也说明它早就是个**边缘哑弹**，第 4 段装配只是压垮它的那根稻草；**调大测试栈不是修法**
（`-Xss` 只是把这个边界挪远，每加一段引导就再来一次）。

**药**：`extractBootstrap` 换成正则等价的**线性扫描** —— 定位声明 → 跳 `=` → 逐个收字面量
（`\x` 两字符原样进 raw、下一个非空白不是 `"` 就收工），转义解码拆去独立的 `decodeCEscapes`；
形态变了（改名/改写法/引号不闭合/末尾孤零零一个 `\`）一律 `check` 报错，不静默抽错。
仓库里同形的"从 C++ 源里正则抠字面量块"只有这一处（已 grep）。

**本机验了什么 / 没验什么（禁本地 gradle）**：① 改后的 `E2EFixtures.kt` 用
kotlin-compiler-embeddable 2.0.21 编过（零 error 零 warning，产出 `E2EFixturesKt.class`）；
② 反射调**真 class** 里的 `extractBootstrap` 跑**真 main.cpp**，四段 `install*` 全部正确还原、

### 2026-10-16 —— 用户裁定：引擎关 stdin 写端发 EOF（自动退）+ 悬浮窗顶栏「结束脚本」

**用户裁定**（对上一版 `unref` 补丁的评审）：四条排序 —— ① **最干净**：引擎关 stdin 写端发
EOF，让 readline 自然收到 end/close、脚本自己结束（"这是正路"）；② 次选：宿主显式结束；
③ 再次：引擎提供专用 `ask()` API；④ **最后才是那个补丁**。用户定的是 **① + 自动退**，
并在悬浮窗**顶栏**要一颗「结束脚本」的钮（不是输入行那颗"结束输入/Ctrl-D"）。

**为什么 ① 是正路**（本机 node 22.23.1 逐条实测）：引擎关掉写端（真 EOF）→ 脚本收到
`stdin 'end'` → readline 发 `'close'` → **408ms、code 0 干净退出**；关键是脚本**能自己感知**
流结束（`process.stdin.on('end')`、`rl.on('close')` 都触发）—— 这是标准流语义，而 `unref`
那套给不了（它只影响"事件循环退不退"，脚本看不见 `end`）。**代价同样实测**：EOF 到得早
（问题还挂着）→ 那个 `question` 回调**永不触发**、readline 直接关、脚本剩下的活静默丢掉
—— EOF 一次性、不可逆，所以"**什么时候发**"必须有判据。

**② 照字面做不到**：`rl.close()` / `process.stdin.unref()` 都是**脚本进程内**的调用，宿主
手里没有 rl、也没有脚本的 `process.stdin` 对象；宿主能做的只有两件：关管道写端（= ①）或
杀进程。超时 `destroyForcibly` **不做默认** —— 跑长活的自动化脚本会被误杀，且超时值没法定。
**③ 不做**：`ask()` 只帮愿意用它的人，标准 `readline` 写法照样挂着 —— 与"脚本写法保持原生"
（2026-10-15 用户令「js 的语法都要和原来的调用方式一样」）相悖。

**药一：脚本侧只报事实（`bridge/js/src/stdin-idle.ts`；kBootstrap 装，与
`installConsoleBridge`/`installReadlineShim` 同一段装配）**。只往 `process.stdin` 挂一个
`'pause'` 监听 —— **'pause' 当闹钟、监听器计数当判据**（`data` 与 `readable` 两个都归零
才叫"没有读者"；readline 在 `close()` 时撤得干净，实测 `dataL 1→0`），判到就报一次
`engines.stdinIdle`（报过置位：EOF 不可逆，一次就够）。**不碰 readline 模块、不 unref**
（上一版被推翻的正是"换全局 `createInterface`"）。**同一个 tick 里"关一个立刻开下一个"
不误判**（`rl1.close(); rl2 = createInterface(…)` 是常见写法，同步判会提前发 EOF，第二个
问题就废了）—— 判据推到 `setImmediate`。脚本自己 `rl.pause()`（流控、监听器还在）不会被
误判；没读过 stdin 的脚本一次都不会报。

**药二：引擎侧关写端（五层，与 `sendInput` 同构）**：`engines.stdinIdle`（**目标恒是自己**
—— runId 取自认证连接身份、payload 里根本没有这个字段；缺身份 `ERR_PERMISSION_DENIED`；
关不了如实回 `Ok false` 而不是错误码，与 `heartbeat` 的 `Ok false` 同一条"如实告知"口径）
→ `RuntimeController.closeStdin`（在途表精确命中，不在途不问引擎）→ `ScriptEngine.closeStdin`
（缺省 false，替身零改动）→ `NodeProcessEngine.closeStdin` → `SpawnedProcess.closeStdin`
（`outputStream.flush()` + `close()`；进程已退/已关回 false 不抛）。目录级能力位 **`NONE`**
（自我操作，与 `stop`/`status` 同口径：路由层看不到 runId，给重档会连"关自己的 stdin"都拒）。

**药三：顶栏「结束脚本」**（用户令；`GlyphKind.STOP` 实心方块，排在暂停/重跑那颗之后）：
`LogWindowController.stop()` → `HostSummary.stopRun`（四步停走）。在途才可点（已结算置灰，
那颗钮没什么可停）；`true` = 已请求停止（不赌停没停）、`false` = 已不在途（`AlreadyGone`
的诚实投影，不假称成功）；已结算**静默早退**（与暂停钮同一条"结算不解绑"口径）。
**它兜的是自动判据管不了的形态**：脚本正卡在 stdin 上等输入（读者还在 → 不报）或死循环/
卡网络 —— 那时用户唯一能收场的手段就是停掉它。

**推翻的记账**：上一版那条（`91929b1d`，进程内 `unref`）**同日 revert（`1e402701`）**；

**守卫**：`stdin-idle.test.cjs` **六条真子进程** —— 答完报一次 / 接口没关不报 / 脚本自己
还挂着 `data` 不报 / 同 tick 重开不误报 / 没动过 stdin 一次都不报 / **闭环：报上来之后父进程

### 2026-10-16 —— 用户问：readline 那段「输出 2 之后过了很久才自动关闭」

**用户问**（在上一批 readline 修好之后）：那段 `rl.question('请输入：')` 的脚本
「为什么它输出 2 之后，过了很久才自动关闭」。

**病**（本机 node 22.23.1 逐条实测）：`process.stdin` 是个**被 ref 住的句柄** —— 只要它还开着，
Node 的事件循环就永远不空；`rl.close()` 只是**不再读**它，**不放开**。三种形态实测：
管道 stdin + `close()` → 挂着；管道 + `pause()` → 照样挂着；管道 + `unref()` → **161ms 就退**。
而且**真 TTY（pty）形态一样挂** —— 真终端里收尾靠的是 Ctrl-D/Ctrl-C，不是 `close()`。
我们这个宿主里没有 Ctrl-D：stdin 的**写端永远开着**（引擎只写行、不发 EOF），脚本等不到
`'end'`，于是"问答脚本答完就结束"这件事**没人做**，用户看到的就是"一直显示在跑"
（真实触发"很久之后关闭"的多半是下一次执行顶替了它 —— 池容量 1，起跑前会把旧的
`destroyForcibly`，或用户自己按了停止）。

**药**（`91929b1d`，仍落在同一个 readline 补丁里 —— 它本来就是"readline 在这个宿主里的
语义补丁"）：记账"stdin 上还活着几个接口"，**最后一个被 `close`** 且 stdin 上不再有
`data`/`readable` 监听（`end` 不算：readline 自己常驻一个，实测 close 后 `data=0 readable=0
end=1`）时 `process.stdin.unref()`；**新建接口时 `ref()` 回来** —— `resume()` **不会**自己 ref
回来（实测：unref 之后新建接口继续等输入，进程 159ms 就退了），少了这一下，"关掉一个再开
一个"的多轮脚本会在第二次提问前排到退出。放开动作**延后一拍**（`setImmediate`）：`close()`
之后同一个 tick 里可能又挂上 `data` 监听（裸 stdin 读法），当场判会把它漏掉。
**边界**：裸 `process.stdin.on('data', …)` 的脚本不受影响（监听检查把它排除在外，
那种写法自己管生命周期）；`ref/unref` 只影响"撑不撑住事件循环"，不影响数据还能不能收。

### 2026-10-16 —— 悬浮窗标题下加分隔线 + 「点输入框外面收键盘」修掉"光标还在闪"（用户报）

**用户令两条**：①「悬浮窗标题下面加个分隔线」；②「目前搜索框，还有输入框都有个 bug。

线画在**块内底缘**而不是两块之间的 8dp 缝里：三块现在同色（第三轮「胶囊也白」），
悬在缝里会像飘着。`dragHandle` 随之上移到这一层（拖拽区仍是整块头部，含那条线）。

**(b) 「光标还在闪」的真因不是闪烁动画，是焦点根本没转移。** 设备实测
（`uiautomator` 读 `focused` + `dumpsys input_method` 读 `mInputShown`）：
点搜索框 → `focused=true`、输入法起来；接着点列表行 / 卡片 / 顶栏 ⋮ → 搜索框**仍然**
`focused=true`、输入法仍开着 —— 此时敲字**落进搜索框**（`adb shell input text ZZZ`
之后列表被过滤成「没有匹配「搜索词」的文件」，而人是想点那一行）。用户看到的就是
"点了别处，光标还在那儿一闪一闪"。

**为什么会这样**：Compose 的 `clickable` 只装 `focusableInNonTouchMode`
（`Clickable.kt` 里那句 `.focusableInNonTouchMode(enabled, …)`，1.7.3 源码实读）——
**触屏模式下它压根不请求焦点**。这是有意的（否则点一下列表就会把输入框的焦点抢走），
代价是「点空白处收键盘」这件事**没人做**：`BasicTextField` 只在别处**主动
`requestFocus`** 时才失焦，而点一个不可聚焦的行不会。原生 `EditText` 那套由平台
（`View.onTouchEvent` → `clearFocus`）兜着，Compose 里得自己接。

**药** = 新增 `ui/components/FocusDismiss.kt` 一对修饰符：
- 输入框挂 `reportFocusBounds(state)`：`onGloballyPositioned` 报**根坐标 bounds**、
  `onFocusChanged` 报**聚不聚焦**（两个回调各管一半：只留前者的话失焦后 bounds 还在，
  下一次点空白会被判成"点在框里"而不收键盘）；
- 容器挂 `dismissFocusOnTapOutside(state)`：在 **Initial 趟**读按下点（父→子那一趟，
  子节点还没消费；**只读不消费**，列表滚动 / 行长按 / 日志拖选全照旧），落在输入框
  bounds 之外就 `clearFocus()`。

**为什么按 bounds 判而不是"看谁消费了事件"**：消费分不出"点的是输入框"还是"点的是行"
—— 两边的 `detectTapAndPress` 都会 `consume()` 掉那个 down（`TapGestureDetector.kt` 实读）。

**三处接上**：项目页（挂在 `ManagementTransition` 的 modifier 上 —— 那样点编辑面那一下
也算"点外面"）、任务中心（根 `Column`）、悬浮窗（内容根 `Column`）。

**已知取舍（如实记，不假装测过）**：① 一份 state 是**单槽位** —— 同一面里两个输入框时
以"最近聚焦者"为准；三处用到的地方各自只有一个输入框，真要多槽位再改，不先造机制。
② `clickable` 在**非触屏模式**（外接键盘/鼠标）下仍会请求焦点，那条路径本仓不覆盖
（设备是触屏）。

—— 那是"发消息出去"，这颗是"送进正在跑的那个脚本"）。设备侧观感（软键盘弹出后窗是否被
顶、全屏态下的输入行位置）待用户真机回执。

### 2026-10-16 —— 三条用户报：崩溃病因进悬浮窗 + 跨窗口收键盘 + 兜底补位号加归属过滤

**用户报三条**：①「悬浮窗的输入框，在我点击软件非悬浮窗界面的时候，还有光标。点击搜索框时，
在点击悬浮窗也不会消失」；②「新增的这个脚本，运行的时候会执行上一次执行成功的脚本，
而不会接收输入内容」（脚本是 `const input = prompt("请输入：")` 那段）；
③「有不支持的函数应该在悬浮窗里输出报错啊」。

**(a) 崩溃病因进控制台（③，`449b2e42`）**。病：脚本抛错（`ReferenceError: prompt is not defined`
这类）的唯一载体是 `RunSummary.stderrTail`，它只进档案的 `crashSummary`（任务日志详情才读得到），
控制台/悬浮窗一行都没有 —— 窗里画的是「本次执行没有输出（已结束）」，用户读到的是"脚本没反应"。
药：`ControllerRunDispatcher` 加 `crashLine` 缝（缺省不写，替身零改动），结算为
Failed/Crashed/StopTimeout 且有进程摘要时按 `error` 档写一行，**归属仍是这次 runId** ——
与脚本自己的 console 行同一条数据面、同一个归属过滤，于是悬浮窗/控制台/日志管理三处同时看得见
（`AppShell.assemble` 接 `ConsoleCollector::append`，落盘 sink 随之生效，详情页也读得到）。
`crashText` 无 stderr 尾部时不编"崩了"（退回只报退出码）—— 空话会让人以为看见了病因。
守卫两条：崩溃必写一行且归属非 0 / 跑成功不写。

**(b) 跨窗口收键盘（①，`738aaa0b`）**。病根坐实：`dismissFocusOnTapOutside` 只看得到
**自己那棵组合**里的指针事件，而系统悬浮窗是**另一个窗口**
（`SystemLogWindowHost` 的 `TYPE_APPLICATION_OVERLAY` + 离屏 `ComposeView`），两棵 Compose 树
各有自己那份 `FocusManager` —— 点 A 窗口这件事 B 窗口永远不知道。药两条互补的路
（都不依赖 WMS 的窗口焦点行为）：`FocusDismissRegistry` 分两档 —— `clearSeparateWindows`
（应用窗口收到触摸 → 清独立窗口那份，落点 `MainActivity.dispatchTouchEvent`）与
`clearAppFaces`（悬浮窗被点 / 其输入框拿到焦点 → 清应用侧各面那份）；外加
`DismissFocusOnWindowBlur`（切后台/分屏那一路，走 `LocalWindowInfo.isWindowFocused`，
Compose 1.7.3 仍标 `@ExperimentalComposeUiApi`，反编译实证后加 `@OptIn`）。
**两档互斥而不是互相清全部**：清自己会打断正在进行的输入（点输入框内部放光标 → 清一次再聚焦
→ 输入法闪一下）。in-app 兜底窗**不在**"独立窗口"那一档（与 Activity 同窗口，自己看得见点按），
角色由宿主传 `separateWindow` 进来 —— 内容层是两个宿主共用的，角色不能自己猜。

**(c) 兜底补位号加归属过滤（②，`70f26234`）**。病根：快速脚本的兜底补位号取的是
**全库**最新的非引擎外行（`consoleState.scriptOutputLines().maxByOrNull { it.runId }`）——
没有归属过滤。窗刚开、还没被在途表绑上那一刻，只要控制台里存着任何更早的执行行，
补位就把窗绑到那条上：标题是这次的路径、行区画的是上一次的输出、重跑钮点下去跑的也是窗里那个
旧绑定 —— 读起来正是"它跑了上一次那个脚本"。药：`fallbackRunIdFor(state, rows)` 从落盘执行索引
（每条都带 `projectId` + `scriptPath`）按**同一套归属判据**（projectId + 项目内 relPath 全等）
挑最近一条 run；调用方只在窗"从没绑上过"（`boundRunId == null`）时才查（成本不进常规轮次）。
另：重跑前先确认窗里那个文件还在（读一次，与引擎侧同一条 `ScriptFileOps` 判据）——
缺文件的真相此前只有引擎侧 `ERR_FILE_NOT_FOUND`，落在意图日志/档案里，窗里看到的是
"没有任何新输出"；现在当场 toast 说清楚。守卫四条（别的脚本再新也不补 / 同归属取最近 /
别的项目不算 / 一条都没有回 null）。

**未做**：`prompt()` **不加**（用户选定「不加，改用 readline」）—— Node 里没有全局 `prompt`
（本机实跑：`ReferenceError: prompt is not defined`，exit 1），仓里只有 `auto.dialogs.prompt`
（async、走桥）；脚本改用 `readline`/`process.stdin` 即可，悬浮窗输入框已经通到 stdin。

### 2026-10-16 —— 悬浮窗标题下加分隔线 + 「点输入框外面收键盘」修掉"光标还在闪"（用户报）

**用户令两条**：①「悬浮窗标题下面加个分隔线」；②「目前搜索框，还有输入框都有个 bug。
就是点击之后，输入指示条在焦点转移后还是会一闪一闪的」。

**(a) 分隔线**：头部那块（标题 + 四钮）从裸 `Row` 改成一个 `Column`，底缘加
`Separator(indentDp = 0)`（通宽 —— 它是"标题栏的底边"，不是列表行那种缩进线）。
线画在**块内底缘**而不是两块之间的 8dp 缝里：三块现在同色（第三轮「胶囊也白」），
悬在缝里会像飘着。`dragHandle` 随之上移到这一层（拖拽区仍是整块头部，含那条线）。

**(b) 「光标还在闪」的真因不是闪烁动画，是焦点根本没转移。** 设备实测
（`uiautomator` 读 `focused` + `dumpsys input_method` 读 `mInputShown`）：
点搜索框 → `focused=true`、输入法起来；接着点列表行 / 卡片 / 顶栏 ⋮ → 搜索框**仍然**
`focused=true`、输入法仍开着 —— 此时敲字**落进搜索框**（`adb shell input text ZZZ`
之后列表被过滤成「没有匹配「搜索词」的文件」，而人是想点那一行）。用户看到的就是
"点了别处，光标还在那儿一闪一闪"。

**为什么会这样**：Compose 的 `clickable` 只装 `focusableInNonTouchMode`
（`Clickable.kt` 里那句 `.focusableInNonTouchMode(enabled, …)`，1.7.3 源码实读）——
**触屏模式下它压根不请求焦点**。这是有意的（否则点一下列表就会把输入框的焦点抢走），
代价是「点空白处收键盘」这件事**没人做**：`BasicTextField` 只在别处**主动
`requestFocus`** 时才失焦，而点一个不可聚焦的行不会。原生 `EditText` 那套由平台
（`View.onTouchEvent` → `clearFocus`）兜着，Compose 里得自己接。

**药** = 新增 `ui/components/FocusDismiss.kt` 一对修饰符：
- 输入框挂 `reportFocusBounds(state)`：`onGloballyPositioned` 报**根坐标 bounds**、
  `onFocusChanged` 报**聚不聚焦**（两个回调各管一半：只留前者的话失焦后 bounds 还在，
  下一次点空白会被判成"点在框里"而不收键盘）；
- 容器挂 `dismissFocusOnTapOutside(state)`：在 **Initial 趟**读按下点（父→子那一趟，
  子节点还没消费；**只读不消费**，列表滚动 / 行长按 / 日志拖选全照旧），落在输入框
  bounds 之外就 `clearFocus()`。

**为什么按 bounds 判而不是"看谁消费了事件"**：消费分不出"点的是输入框"还是"点的是行"
—— 两边的 `detectTapAndPress` 都会 `consume()` 掉那个 down（`TapGestureDetector.kt` 实读）。

**三处接上**：项目页（挂在 `ManagementTransition` 的 modifier 上 —— 那样点编辑面那一下
也算"点外面"）、任务中心（根 `Column`）、悬浮窗（内容根 `Column`）。

**已知取舍（如实记，不假装测过）**：① 一份 state 是**单槽位** —— 同一面里两个输入框时
以"最近聚焦者"为准；三处用到的地方各自只有一个输入框，真要多槽位再改，不先造机制。
② `clickable` 在**非触屏模式**（外接键盘/鼠标）下仍会请求焦点，那条路径本仓不覆盖
（设备是触屏）。

### 2026-10-16 —— 悬浮窗底部输入框 → 脚本 stdin（用户令）+ 胶囊框换白（第三轮配色）

**用户令三条**：①「胶囊框换白色」（问询确认：**窗底保持白+描边，胶囊也白**）；
②「在悬浮窗最下面放一个输入框，输入框右边放一个蓝色的箭头用于输入。输入框样式参考
首页的搜索框，背景灰色的」；③ 箭头语义经问询确认 = **喂给脚本的 stdin**（不是 JS 求值）。

**配色（第三轮）**：`WindowBlockSurface` 从 `surfaceMuted` 换成 `surface`（与窗底同键）
—— 整张卡片是一个白面 + 一圈 1dp 淡灰描边（`editorChipBorder`）。8dp 块间距与 12dp
圆角仍在（结构没变，只是三块同色）。三轮口径的取舍逐条记在 `LogWindowContent` 的
`WindowSurface` KDoc 里（第一轮灰窗白胶囊+阴影 → 用户「效果不太好」；第二轮白窗描边
+灰胶囊；第三轮胶囊也白）。**同色是用户的明确选择，不是漏改** —— 要再把两块分出来
改 `WindowBlockSurface` 一个键即可。

**输入链路（五层，全走 OS 管道，脚本侧零改动）**：
`SpawnedProcess.writeStdin`（`ProcessBuilder` 本来就 `Redirect.PIPE`，此前没人写过；
utf-8 + `\n` + **必须 flush** —— `getOutputStream()` 是带缓冲的包装流，不 flush 会攒在
8KiB 里，脚本永远等不到那一行）→ `ScriptEngine.sendInput`（缺省 false，替身零改动）
→ `RuntimeController.sendInput`（在途表精确命中，与 `pauseRun` 同口径；**暂停中也照送**
—— SIGSTOP 冻的是 CPU，管道内核缓冲照收，解冻后 read 就能拿到）→ `HostSummary.sendInput`
→ `LogWindowController.sendInput`（空白行不发、不在途/已结算不发、成功才清草稿、
失败如实 toast）。脚本用 `process.stdin`/`readline` 照常读 —— 与裸 `console.log` 走桥
那次同一条判据：**让通道迁就脚本的原生写法**。

**系统窗的输入法**（不解决就是"能画不能打"）：那颗窗全程带 `FLAG_NOT_FOCUSABLE`
（类 KDoc 的理由：悬浮窗是"贴在旁边看"的，抢焦点会把用户正在操作的输入法顶掉），
而**不可聚焦的窗口拿不到 IME**。药 = `SystemLogWindowHost.setImeFocus(on)`：输入框
**拿到焦点那段时间**才摘掉 `FLAG_NOT_FOCUSABLE`、加 `FLAG_NOT_TOUCH_MODAL`
（窗外触摸仍落下层 App）、`softInputMode = ADJUST_RESIZE|STATE_ALWAYS_VISIBLE`，
并补一次 `requestFocus`/`showSoftInput` —— **Compose 自己那次请求发生在窗口还不可聚焦
时，是空放的**（顺序不对才是"点了没反应"的形态）。失去焦点即原样加回。原设计那条
理由一字不动。

**草稿住状态层**（`LogWindowState.inputDraft`）而不是内容层 `remember`：两个宿主画
**同一个窗**，而内容层是**无状态**的 —— `remember` 会在系统窗那次 `setContent` 重喂时
把敲了一半的一行丢掉。`sendInput` 成功清草稿时**现读** `state`（挂起期间轮询那一轮
可能已推新值，拿挂起前那份 `copy` 会把那一轮的结果抹掉 —— 本仓反复踩过的"捕获值 vs 现读"）。

**守卫四条**：
- `NodeProcessEngineRealSpawnTest` 新增真起 node 的用例（脚本 `readline` 收到 `甲|乙`
  落盘、行尾由宿主补；**本机先用真 spawn 预演过同一形状**才写进测试）；
- `RuntimeControllerTest`：在途才转给引擎 / 不在途**根本不问引擎** / 引擎说写不进也如实 false
  / 结算后那行不落到引擎上（结算不解绑 ⇒ 窗里绑着一个跑完的号是常态，这条是主要防线）；
- `LogWindowControllerTest`：成功才清草稿 / 不在途与已结算都发不出去 / 空白行连话术都不弹；
- 替身各补一条：`FakeEngine.sendInput`（`sentInputs` 账 + `sendInputResult` 开关）、
  `FakeHost.sendInput`（响亮 `UnsupportedOperationException`，与同类成员同形）。

**detekt**：本机用 gradle 缓存里的 `detekt-cli 1.23.8` + 仓级 `build-logic/detekt.yml`
跑了**全部 15 个源面**（与 CI 同一条配置与 baseline 机制）—— 这是"本机不跑 gradle"之下

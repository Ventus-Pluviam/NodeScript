### 2026-10-14 —— 点执行零输出：引擎三件 `.so` 读错目录（批 109 改名连带，nsDir/nativeLibDir 串位）

**用户报告**：「文件列表点击执行后没有输出。悬浮窗内提示本次执行未开始」。

**现场**（设备 intent log 里那一条，原文）：

```
ERR_FILE_NOT_FOUND: 文件不存在 —— 引擎宿主二进制未随 APK 落位：
/data/user/0/com.autoscript/files/.ns/libnoden.so（jniLibs 交付，node-runtime-build CI 产物，§19）
```

文件实际在 `nativeLibraryDir/libnoden.so`（`app/build.gradle.kts` 的
`useLegacyPackaging = true` 就是为「安装期解压出真文件」设的）。全链其余各段都健康：
`demo/main.js` → 内部相对路径转换正常、`CRASHED` 如实落账、悬浮窗因绑不到在途 run
而显示空态（「本次执行未开始」是**症状**不是病）。

**根因 = 改名的碰撞**。`e338000`（批 109，typed ids）的 `.autojs` → `.ns` 批量改名里，
局部 val `autojsDir` 改成 `nsDir`、`nativeDir` 改成 `nativeLibDir`，而三个调用点被
逐字符替换成了 `nsDir`：

```diff
-  hostBinary = nativeDir.resolve("libnoden.so"),
+  hostBinary = nsDir.resolve("libnoden.so"),        // 应为 nativeLibDir
-  npmNodeBin = nativeDir.resolve("libnoden.so").toString(),
+  npmNodeBin = nsDir.resolve("libnoden.so").toString(),
```

Kotlin 不报错（两个都是 `Path`、`resolve` 都合法）——`design-decisions.md` §77.3 记的
正是这种形态（上一次是 `autojsDir` 撞名）。三处全错：`hostBinary`、`libnodePath`、
`npmNodeBin`（npm 执行体的宿主，同一条链上另一个受害点，只是本次没触发）。

**CI 为什么全绿**：JVM 侧走假引擎（`FakeEngineForDispatcher`）或 PATH 上的系统 `node`
—— `NodeEngineConfig.hostBinary` 的**非绝对路径跳过存在性预检**，两条都不碰这三个路径。
只有真形态 APK 在设备上跑才会走到。

**药 + 门**：三处改回 `nativeLibDir.resolve(…)`；新增 `AppShellEnginePathsTest` ——
三个接收者同型（都是 `Path`），类型系统没有可判的区别，能拦的只有「哪一行读的是哪个目录」，
故从源里**现推** `Paths.get(applicationInfo.nativeLibraryDir)` 绑到的 val 名，要求三处
`.so` 路径的接收者都等于它、且都不等于 `filesDir.resolve(".ns")` 绑到的那个。
已拿 `e338000` 那份源验过**会红**（三处全命中），不是一道恒绿的门。

**边界（如实记）**：这道门读源码，不是编译期保证 —— 它只覆盖 `AppShellApplication`
里这三处点名的路径；将来别处再出现同类串位，仍要靠读代码。

### 2026-10-14 —— 固定开发签名密钥：本机与 CI 同签名、可覆盖安装（用户令）

**用户令**：「不要每次编译出来的安装包签名都不一样」。

**病**：`app/build.gradle.kts` 的 debug 与 release 都签 AGP 的
`signingConfigs.getByName("debug")`，而它读 `~/.android/debug.keystore` —— 那是
**每台机器各自生成**的（AGP 首次构建时现造）。于是本机出的包与 CI 出的包签名不同，
**互相盖不上**：装过 CI 的真形态 APK 之后，本机出的包必须**先卸载**才能装（反之亦然），
而卸载连 `filesDir` 一起清 —— 项目、脚本、日志全没，真机复测每次都从零。
设备实测：已装包签名 `SHA-256 01e54b68…`（某次 CI 的临时调试密钥），本机 `~/.android`
那把是 `C5:1E:F5:89…` —— 两把不同，就是这条病的现场。

**药**：仓库收一把固定密钥 `keystore/autoscript-dev.keystore`
（`SHA-256 0F:CD:82:73…`，别名 `androiddebugkey`，口令 `android` —— 与 AGP 调试密钥同约定），
新增 `signingConfigs.dev` 供 debug 与 release 共用；`.gitignore` 的 `*.keystore` 仍在，
只对**这一个路径**开例外。口令支持 `AUTOSCRIPT_DEV_KS_PASS`/`AUTOSCRIPT_DEV_KEY_PASS`
覆盖（缺省 `android`）—— 那不是安全措施（密钥本身就公开），只是让"换成私有密钥"不必改代码。
与 `:app-service:packager` 那对 `AUTOSCRIPT_KS_PASS`/`AUTOSCRIPT_KEY_PASS` 是**两回事**
（那边签的是打包链产出的用户 APK，口令不进 argv，见 `SECURITY.md`）。

**边界（如实记）**：这是**开发密钥，不是发行密钥** —— 在公开仓里人人可取，用途只有
「开发期两端互相覆盖安装」。本仓不发行正式版（§18 第 3 项），正式签名轨在
`:app-service:packager`（§14）；真做发行时另起一把，别用这把。

**与 `SECURITY.md` 的一处口径冲突（留给维护者）**：该文件（冻结面）写着「密钥库文件
（`*.jks`/`*.keystore`）已列入 `.gitignore`，**不要提交进仓库**」。本条令把一把**开发**
密钥收进了仓库 —— 该文件那句需要维护者按本决定补一句"开发签名密钥例外"，否则两份口径打架。
本批**不动 `SECURITY.md`**（冻结面）。

**一次性代价**：设备上现装的那份是旧临时密钥签的，换新密钥后**必须卸载一次**
（`filesDir` 一并清空）—— 此后不再有这一下。

### 2026-10-14 —— 「点执行就闪退」修法（用户复报后）：离屏组合四层收口，全部 fail-closed

**根因链**（本机禁 gradle，全部代码核实 + javap 反汇编，无运行期可复现）：

- `SystemWindowSync` 的内容效应跑在 `LaunchedEffect` 里，而组合协程域**没有
  `CoroutineExceptionHandler`**（javap 核实 compose 1.7.3 `createCompositionCoroutineScope`
  只挂 Job）—— 效应里一抛就是**进程终结**，没有静默吞掉的回路。
- 此前内容效应键含 `lines`（`consoleState.lines`），而轮询 400ms 一轮、每轮
  `ConsoleState.of` 都产出**新的 `List` 实例** → 窗一开就每 400ms 重跑一次
  `show()` 的重喂分支，而那条分支是**裸 `setContent`（没有 catch）** —— 组合期
  一抛顺着调用栈冒到进程。
- 三条 ISE 逃逸路径：`runFileWithWindow` 的 `logWindowRef()`（`checkNotNull`）在 try
  之外；`runTaskNowOp` 里同样那句跑在 `scope.launch`（组合作用域）；`ProjectScreen.runFile`
  的 catch 链没有 `IllegalStateException`（宿主「■ 链」的 `error("壳未装配…")` /
  `check(!sinking)` / `IllegalStateException("任务不存在…")` 全落空）。

**四层收口（宁可看得见的降级，不闪退）**：

1. 行数据从参数改住 `LogWindowController.lines`（Compose 状态，窗内**现读**）——
   `setContent` 执行次数 = 开窗次数，行刷新走普通重组；`show()` 重喂分支补上
   与首建同款 `catch`（失败 hide + 回 false，调用方经 `fallbackToInApp()` 落 in-app 回退窗）。
2. `runFileWithWindow`：开窗挪进 try；失败清理改走 `logWindowRefOrNull()?.close()` ——
   清理路径**自己不许再抛**（拿不到控制器恰恰是它要处理的那种失败）。
3. `runTaskNowOp`：开窗失败退成「没有悬浮窗的那次立即执行」—— 任务照跑，
   结局在控制台/任务日志；跑失败（opError 非空）才关窗。
4. `ProjectScreen.runFile`：catch 链补 `IllegalStateException` → 弹失败 toast（亮原文，
   不上抛）。

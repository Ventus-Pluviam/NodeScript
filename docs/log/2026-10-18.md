### 2026-10-18 —— 依赖页第十二批：**把依赖清单那条链路上说得清的白扔去掉**（派生属性改算一次、`@Immutable`、item 类型分开报、列表行里的胶囊不再带动画）

**用户口径原文**：「**滑动起来还是很卡啊，首页的文件列表就不卡。好好优化啊**」。

**先说实话：本机测不了帧率**（不跑 Gradle、不连设备、禁 adb 截图/读屏），所以这一批不是
"测出来修好了"，是**把这条链路上能指名道姓的浪费一处一处去掉**。下面每一条都能在代码里
指出它原先在扔什么。

**一、`NpmState` 上五个派生属性从 `get()` 改成"算一次、留着"**（`by lazy(LazyThreadSafetyMode.NONE)`）。
这不是风格问题，是**每读一次就重算一遍**：

- `installed`：从前是个 `get()`，**每次读都把整份依赖清单 `.map` 一遍**、造一整列新的
  `NpmRowState`。而依赖列表的组合要读它，**卡头那句条数还要为了一句长度再读一次 `.size`**
  （`state.installed.size` —— 又映射一整个列表）。包一多，这就是按次数的平方白扔。
- `logLines`：从前每次读都 `buildList` 一遍，里面每一行还要拼一次 `timeText + "  " + text`。
- `sizeLabel` / `cacheSizeLabel`：从前每次读都跑一遍 `String.format`（`bytes()` 的 MB 那一档）。
- `project`：从前每次读都线性扫一遍 `snapshot.projects`。
- `NpmRowState.sizeLabel` 同理，从 `get()` 改成 `val`。

**取"算一次"而不是"每次读现算"**：一份 `NpmState` 是不可变的（全是 `val`，改是 `copy` 出新的
一份），这份投影在它的一生里不会变 —— 算一次就够。不进构造函数里现算是为了不让每次 `copy()`
（安装框里**每敲一个字**就是一次 `copy`）都付一遍这份钱。

**二、`@Immutable` 加在 `NpmState` / `NpmRowState` 上。** 不标它，`NpmState` 在编译器眼里是
**不稳定类型**，于是 `NpmScreen` 与它每个收 `state` 的子件（`ScopeCard` / `InstallRow` /
`LogCard` / `OptionsBar`）**一律不可跳过**：外壳每重组一次，这一整片就跟着重来一遍 ——
而外壳是会重组的（上面那个 `copy()` 一次就是一次）。全字段 `val` + 列表只整体换新（
`consoleLines` 只用 `+` / `emptyList()` / `takeLast` 换，从不原地改）是这条承诺的凭据。

**三、列表 item 的 `contentType` 各报各的。** 这一屏有六种形状（作用域卡 / 安装段 / 卡头段 /
空态段 / 依赖行 / 日志卡），此前全报 `null` —— 共用一个复用池，等于让 LazyColumn 拿
"安装输入行"的槽位去装"一颗依赖"。现在分开报，且**作用域卡与日志卡也分开**（两者都是
`PanelCard` 那层皮，但内容形态不是一回事）。

**四、三处文字限一行 + 省略号**（照首页 `FileRow` 的写法）：包名可以很长
（`@babel/plugin-transform-async-generator-functions`），不给上限就换行 —— 一行的排版高矮
不一，滚动时要一遍遍重排、上下跳动。

**五、三个圆角 `Shape` 提成文件级常量**，不再每段 item 现造一个。

**六、`PillButton` 新增尾参 `animated: Boolean = true`；依赖行传 `false`。** 这是这一批里
**唯一直接冲"每一行进入视野时的成本"**去的一条：`animateColorAsState` 是按实例建 `Animatable`
的，每多一颗胶囊就多两个 `Animatable` + 两条订阅协程 + 两次 `SideEffect`，而这些是**跟着每一行
滚进视野现造、滚出视野丢掉**的。而依赖行那颗「卸载」的选中态是写死的 `false` ——
**那条动画一辈子不会真的跑一帧**，纯白扔。分段控件那一档照旧带动画（缺省 `true`）。

**七、勘误（只追加纪律下的原地订正，不删原文）**：第十一批那句
「这一屏从头到尾只有**一个**可滚动容器」**不准确** —— 日志框 `LogCard` 里那个 `LazyColumn`
还在，它是第十批有意留的。第十一批撤掉的是**依赖列表**那一层。原文已原地划掉并注明日期。

**八、这一批解释不了"为什么首页不卡"**：首页那份文件清单只有几条，而依赖清单可能几百条 ——
两者差的不只是每行的成本，还有**列表长度**。所以本机给不出"修好了"的结论，需要设备上两个数：
**依赖条目量级**（几十还是几百），以及**控制台页 / 日志管理页的列表滚动是否也卡** ——
三个管理子页走的是同一个 `ManagementTransition` 外壳（子页内容外面套着两层全屏 `graphicsLayer`：
位移/缩放那层 + 窗口圆角 `clip` 那层），而首页在 `HorizontalPager` 里、**没有这两层**。
若子页都卡，那一层才是嫌疑；这条本批**没动**（那是逐字复刻 TG 的手势动画，凭猜改它风险大于收益）。

**九**：:ui 编译通过（main + test）、:ui detekt（0 smells；`PillButton` 按精确签名文本在
baseline 里补 `animated` 那一项）、31 个 :ui 测试类全绿。

### 2026-10-18 —— 依赖页第十一批：**安装与依赖列表合成一组** + **三颗动作钉在页底** + **撤掉卡里那层滚动**

**用户口径原文**：「**安装依赖和依赖列表合并成一个列表分组**」「**三个按键放在低栏最下面的
位置**」「**依赖列表滑动还是很卡**」。

**一、安装依赖与依赖列表并成一张卡。** `InstallCard` 与 `DependencyListCard` 合成一组
（`dependenciesGroup`）：**安装行一段、卡头一段、之后每颗依赖各一段**，整组由 `cardSlice`
拼成一张白卡（相邻两段同色贴紧，缝看不见）。上一批那条「依赖列表默认收起」照旧。

**二、三颗维护动作搬出列表，钉在页底。** 新 `OptionsBar`：从前它是 `LazyColumn` 里的一条
item，随内容滚 —— 想按的时候得先滑到它那儿，而这一页上半部分可以很长；现在任何时候都够得着。
让位（`TabBarBottomClearance`）随之从列表的 `contentPadding` 挪到这一栏身上，是同一件事换个
地方做，不是多让一份。列表那侧只留一道卡间缝。**第十批第 28 条「日志在滚动内容最下面」一个
字没改** —— 动作栏不占列表位置。

**三、卡里那层 `LazyColumn` 撤掉。** 这条是上一批报的"卡"接着查下去的结果。此前依赖列表是
**卡里再套一个 `LazyColumn`**（高度上限 `DEP_LIST_MAX_HEIGHT` = 300dp），于是这一屏有**两层
竖向滚动**：拖动要在两层之间交接、内层滚到头外层才接管，手感是断的。现在依赖行是页面列表
自己的 item，~~这一屏从头到尾只有**一个**可滚动容器~~ **订正（2026-10-18 第十二批）**：这句说过头了 —— 撤掉的是**依赖列表**那一层；页底那个日志框（`LogCard`）里的 `LazyColumn` **还在**（`LOG_MAX_HEIGHT` = 200dp 封顶，第十批有意留的，贴底靠 `LazyListState` + `animateScrollToItem`）。准确的说法是「依赖列表不再是卡里的第二层滚动」。

顺带两处：`DEP_LIST_MAX_HEIGHT` 常量与它那条 KDoc 一并删除；`cardSlice` 的**中间段不挂
`clip` 图层**（四角是平的，没有圆角要裁住内容，`graphicsLayer` 是白挂的），底色一律走
`background(color, shape)`（按形状画一块，不挂图层）。

**四、这一条我修的是结构，"卡不卡"没测过。** 摊平之后是**只有可见的行才组合、才绘制**
（此前整组是一条 item，比屏幕还高时**整条**都要重画）；但本机不跑 Gradle、不连设备、禁
adb 截图/读屏，帧率测不了 —— **不把"改成了标准结构"讲成"已经不卡了"**，得在设备上看。

**五、核对**：:ui 编译通过（main + test）、:ui detekt（69 文件 / 0 smells，baseline 里
`DependencyListCard` 条目删除、`InstallCard` → `InstallRow`、`OptionsCard` → `OptionsBar`
各按精确签名文本改；`dependenciesGroup` / `cardSlice` / `sliceShape` / `depsTitle` 都是
小写开头的普通函数，不用新增条目）、31 个 :ui 测试类全绿。

### 2026-10-18 —— 依赖页第十批：**日志挪到整页最下面** + **查「依赖列表滑动只有 60 帧」**

**用户口径原文**：「**把日志放到最下面吧**。还有就是**依赖列表滑动起来帧率怎么只有60**」。

**一、日志挪位。** `LogCard` 从"依赖列表与三颗维护动作**之间**"移到**整页最后一段**，新的
自上而下顺序：作用域与尺寸 → 安装 → 依赖列表 → 三个维护动作（`OptionsCard`）→ **日志**。
更早那条「选项放在最下面」（第六批第 22 条）在本条被改写：动作后面还有日志。
两版口径都不删 —— 第 22 条原地划掉并注明改写者，本条记第 28 条。
顺带把两处注释里"往**上**看结果"的读法改成"往**下**看"（框位置变了，那句话也跟着变）。

**二、帧率这件事，先说实话：本仓没有任何一处设置帧率。**
全仓 grep 过 `preferredRefreshRate` / `setFrameRate` / `preferredDisplayModeId` /
`Choreographer` / `withFrameNanos` / `refreshRate` —— **一条都没有**（两份
AndroidManifest 里也没有 `hardwareAccelerated` 之类的条目）。Compose 的帧时钟跟着显示器的
vsync 走，我们既没锁 60，也没有"限帧"的开关可关。所以"只有 60"这个现象**不是本仓某一行
代码直接写出来的** —— 它要么是面板/系统这一档（自适应刷新率、或"标准 60Hz"那一档），
要么是平台按应用出帧速度投票后回落。**这一条我无法在本机证实或证伪**（本机不跑 Gradle、
不禁令外不连设备、禁 adb 截图/读屏），这里只报能落地的那半。

**三、能落地的半：这条链路上确有一处「每帧分配」，已修。**
`Canvas` 的绘制 lambda **每一帧都重跑一遍**（列表滚动时可见行每帧都要重画），而
`ui/src/main/kotlin/com/autoscript/ui/components/Glyphs.kt` 里原来的
`path(...)` 是 `Path().apply { … }` —— **每画一笔新建一个 `Path`**。Compose 的 `Path` 背后是
Skia 原生对象，于是**每一个可见字形、每一帧**都在造 1~4 个原生对象再丢掉（底栏 5 个 +
顶栏 + 依赖列表**每一行**那两个 ⟳ 与胶囊…）。滚动时这是纯粹的白扔，也是这条链路上唯一
**可证**的一处每帧开销。

改法：`Glyph` 里加一个 `remember` 挂在本节点上的 `GlyphScratch` 小池子 —— 绘制开头
`begin()`，之后每个 `path()` 取池子里下一条并 `reset()`，`Stroke` 按 `(u, weight)` 缓存。
**80 处 `path(...)` 调用点一处没改，字形几何逐条等价**。复用安全的三个前提写在
`Glyph` 的 KDoc 里（每个 `path(...)` 都立刻喂给 `drawPath`，没有 `val p = path(...)`
把两条 Path 同时留活的写法；池子按节点隔离；绘制 lambda 在 UI 线程录制期跑）。

**这不是"60 帧的答案"，是"这条链路上唯一说得清的一处浪费"。** 它能不能把那 60 顶上去，
本机测不了 —— 得在设备上看（Android 开发者选项的"显示刷新率"或 GPU 呈现模式）。

**四、核对**：:ui 编译通过、:ui detekt（69 文件 / 0 smells，`GlyphScratch` 是 class 不是
`@Composable`，不需新增 baseline 条目）、31 个 :ui 测试类全绿。

### 2026-10-18 —— 依赖页第九批：**触感去掉**

**用户口径原文**：「**震动？我不需要震动，去掉吧**」。

第八批按「实现触感反馈」补的那条 `LONG_PRESS` 触感**整个去掉**：`OPTION_TILE_HAPTIC_DELAY_MS`
与那段 `PressInteraction` 订阅一并删，三个 import（`PressInteraction` / `HapticFeedbackType` /
`LocalHapticFeedback`）也删。

**为什么这次不留着**：第八批那条是照着 TG `ProfileActionsView.onTouchEvent` 的
`ACTION_UP` 分支搬的（按住 > 250ms 且手指仍在格内 → `HapticFeedbackConstants.LONG_PRESS`），
但 TG 那是"长按有别的语义"的资料页动作行；本页这三颗按下去就出结果，**没有"长按"这层语义**，
震动就只是多余的打扰。**口径以用户为准**，源码有这条不等于本应用要这条。

**留下的两件事照旧**：缩放回弹（`ButtonBounce`，0.96 / 60ms 按下 / 350ms 过冲回弹）与
"没有「进行中…」文字"（第八批撤的）都不动。

**核对**：:ui 编译通过、:ui detekt 69 文件 0 smells、31 个 :ui 测试类全绿。

### 2026-10-18 —— 依赖页第八批：**撤掉「进行中…」文字** + 补上 TG 的**长按触感**

**用户口径原文**：「**撤掉，实现触感反馈**」。

**一、「进行中…」撤掉。** 那颗文字是第七批之外我自己加的（上一轮已如实说明「不是 TG 的」），
现在按用户口径撤掉：`OptionTile` 的 `running` 参数、三个调用点传的
`busy == NpmMaintenanceAction.PRUNE` / `DEDUPE` / `state.reclaimingCache`、以及 `OptionsCard`
里那个 `val busy` 一并删除。**状态并没有因此消失**：`canInstall` / `canReclaimCache` 在安装会话
期间本来就是 false（安装、维护、回收三者互斥），三颗一起变灰就是状态本身。
这也与 TG 一致 —— 这三颗（`SET_PHOTO` / `EDIT_INFO` / `SETTINGS`）的 `supportsLoading` 是
**false**，那套横向扫光的 `LoadingDrawable` 只挂在 gift / call / video / join / report / leave /
voice / stream / stop 上（`ProfileActionsView` 的 `switch (key)` 分支里逐个赋的值）。

**二、触感照 TG 的口径实现。** `ProfileActionsView.onTouchEvent` 的 `ACTION_UP` 分支：
`System.currentTimeMillis() - downTime > 250` 且 `hit.rect.contains(x, y)` 时
`performHapticFeedback(HapticFeedbackConstants.LONG_PRESS)`。两个要点：

- **不是按住过程中震，是松手那一刻按"按了多久"决定震不震** —— 照这个口径实现：
  从 `PressInteraction.Press` 记下按下时刻，`Release` 时比 `250ms`，`Cancel`（滑走/取消）不震；
- 门槛值取源码原值 250ms（`OPTION_TILE_HAPTIC_DELAY_MS`）。

实现走 `MutableInteractionSource`（与缩放回弹共用同一个 source），不用自己接管 `pointerInput`
—— `clickable` 已经在发这三个交互，多收一路即可，语义（无障碍、禁用、滑走取消）全部沿用。

**三、核对**：:ui 编译通过、:ui detekt 69 文件 0 smells（baseline 的 `FunctionNaming` 条目按
精确签名文本改掉 `running` 那一段）、31 个 :ui 测试类全绿。

### 2026-10-18 —— 依赖页第七批：三个动作格**改成照 TG 源码做**（`ProfileActionsView`），按压从水波换成 `ButtonBounce` 缩放回弹

**用户口径原文**：「**你去看tg源码啊，/tmp/tg**」「**你对着图做干嘛**」。

**一、推翻的是"取值来源"，不是版式。** 昨天第六批那三张等宽白卡（图标在上、文字在下）版式照旧；
被推翻的是**几何的来源** —— 那版是拿用户给的截图当尺子量的（定标卡高 88dp），量出来的是
「88dp 高 / 20dp 圆角 / 32dp 图标 / 16sp 文字」。现在一律改取
`TMessagesProj/src/main/java/org/telegram/ui/Components/ProfileActionsView.java` 的**源码原值**：

| 项 | 源码出处 | 值 | 昨天量的 |
|---|---|---|---|
| 高 | `ProfileActionsView(context, dp(74))` − `ypadding(12)` − `top(8)` | **54dp** | 88dp |
| 圆角 | `getRoundRadius()` = `dp(16)` | **16dp** | 20dp |
| 图标 | `updateBounds()` 的 `drawableSize = dp(24)` | **24dp** | 32dp |
| 文字 | `new Text(cs, 11, AndroidUtilities.bold())` | **11sp 粗体** | 16sp 常规 |
| 横缝 | `betweenPadding = xpadding / 2f`，`xpadding = dpf2(14)` | **7dp** | 12dp |

**参考图就是这一行**：`MODE_MY_PROFILE` 的三颗 `KEY_SET_PHOTO` / `KEY_EDIT_INFO` / `KEY_SETTINGS`
（`addCameraAction()` / `addEditInfo()` / `addSettings()`）—— 查到源码之后，截图与源码是自洽的，
差的那几个数是**我定标定错了**（把卡高当 88dp，实际是 54dp）。

**二、按压换掉：TG 这一行不是水波。** `ProfileActionsView.onTouchEvent` → `hit.bounce.setPressed()`，
`ButtonBounce` 按下 `pressedT` 走 **60ms** / `CubicBezierInterpolator.DEFAULT`
（`cubic-bezier(0.25, 0.1, 0.25, 1)`）到 1，松手 **350ms** / `OvershootInterpolator(5f)` 回 0；
缩放量 `getScale(0.04f)` = `0.96 + 0.04 × (1 − pressedT)` → 按下整格缩到 **0.96**、松手带过冲。
Compose 侧照此实现（`animateFloatAsState` + `graphicsLayer`，按下 `tween(60)`、松手一条高回弹弹簧）。
**`Modifier.pressableRipple` 整件删除**：它是昨天为这三格写的，现在没有调用方了。
（那条 M3 `ripple(color)` 只借 RGB、alpha 被换成 `pressedAlpha` 的反编译结论随代码一起消失，
口径记在[决策第 100 项](../design-decisions.md)。）

**三、两处刻意不照源码，都是为了跟本页对齐**（写进 KDoc）：左右外边距用本页的 `CARD_MARGIN` 12dp

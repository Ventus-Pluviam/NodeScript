### 2026-10-15 —— 悬浮窗三态真机冒烟补记（重跑点/长按都真实再跑，在途态如实画暂停）

上一节「待真机回执」的部分已实机钉死（装 `c482d6f` 真形态 APK，引擎真实跑）：

- **重跑命中（点）**：demo 跑完窗口第一颗钮 `content-desc="重新执行"`（`[546,78][654,182]`），
  `input tap 600 130` → `script-logs/index.jsonl` 新增 `{"run":12,…}`、`12.log` 五条 demo 行齐全 ——
  **重跑 = 引擎真实再跑同一文件成立**。此前 `432bb36` 点重跑无新 run 的根因正是**路径形状**：
  窗内 relPath 是项目内形状（`data/test.js`），直透 `runScriptFileOp` 在
  `AssembledShell.runScriptFile` 的 `ScriptPaths.projectInternalOrNull` 处 `require` 失败
  （首段非项目名）；`2b8b372` 反推首段（`$projectId/$relPath`）后恢复。
- **重跑命中（长按）**：`input swipe 600 130 600 130 800` → 新增 `{"run":13,…}` —— 长按同语义成立。
- **在途态如实画暂停**：注入 8×1.2s 的慢脚本（临时 `files/scripts/demo/slow.js`，冒烟后已删），
  跑动中 dump → 第一颗钮 `content-desc="暂停执行"`、标题 `/demo/slow.js`（无「· 已结束」）、
  行区逐 tick 长 —— 三态图标的在途档在真机上可见。
- **暂停 → 已结束**：点暂停后进程冻不住（云手机无 root、引擎子进程独立 uid，`kill -STOP`
  跨 uid 失败），脚本照跑完 → 窗口结算态标题缀「· 已结束」、第一颗钮回到
  `content-desc="重新执行"`。暂停失败的话术 toast 是 Compose 浮层（非系统 toast），
  `uiautomator dump` 竞不过 1.6s 展示窗口捕不到 —— 该话术由 `LogWindowControllerTest`
  JVM 钉住（在途且宿主 false → 如实 toast），设备侧只能钉到「按钮三态 + 结算收尾」。

**结论**：三态图标的呈现与重跑动作在真机上全链路通；暂停在**有 root / 同 uid 可冻**的设备上
才生效（本台云手机冻不住 —— 如实 toast，非故障）。

### 2026-10-15 —— 悬浮窗第一颗钮三态（暂停/继续/重跑）+ 重跑走引擎真实再跑（用户令）

**用户令**（对第 3 条目的追问「暂停功能是有效的吗」之后）：脚本**执行完**，悬浮窗第一颗钮
从暂停图标变成**重新运行**图标；**执行一半停了**（被暂停/被停），变成**继续执行**图标；
长按这颗钮也是重跑。重跑 = **引擎再跑同一文件**（真实重新执行，不是重放旧日志 —— 用户
**拍板**确认）。

**病**：① 执行完点暂停弹「该执行不支持暂停」—— 它已**结束**，不是"不支持"（结算本来就是
暂停的终态）；② 重跑链把窗里的**项目内**形状 relPath（`data/test.js`）直接透传给
`runScriptFileOp`（收**文件清单**形状，首段 = 项目名）—— `AssembledShell.runScriptFile`
的 `ScriptPaths.projectInternalOrNull` 当场 `require` 失败（**2026-10-13 批 73 的教训在
重跑链上复发**，实机表现：点重跑无新 run、toast 被吞）；③ 快速脚本在两轮轮询间起跑即结算、
从没绑上过 → 窗停在「本次执行未开始」。

**药**：
- 内容层（`LogWindowContent`）只看 `state` 画三态图标与文案（`paused → 继续执行` /
  `running → 暂停执行` / 已结算 → `重新执行`），动作由 `MainActivity.windowFirstAction`
  一个地方分派（点与长按同一语义）；`WindowIconButton` 加 `onLongClick`，走全仓
  `pressableLongPress`（`combinedClickable`）；图标复用 `GlyphKind.RUN`，不新增字形。
- **已结算暂停静默早退**：`LogWindowController` 记 `settledRunIds`（`bind` 观察到「仍绑着
  但不再 running」即入账），`togglePause` 对其**一问不问直接返回** —— 不再把「已结束」
  翻译成「该执行不支持暂停」。在途且冻不住 → 如实 toast。
- **重跑**：`windowFirstAction` 对已结算态先 `LogWindowController.rerun`（窗切到新归属的
  重跑态，跑起来后轮询 `bind` 看到同归属新 run 在途自动换绑）再走 `runScriptFileOp`
  （与 ▶ 同一条执行链）；路径**反推首段** = `projectInternalOrNull` 的逆运算（`$projectId/$relPath`，
  窗的 relPath 恒为削过前缀的形状，不会双份前缀）。失败 → toast 原文、窗留重跑态可再点。
- **快速脚本兜底补绑**：`LogWindowState.bind` 增 `fallbackRunId`（从
  `consoleState.scriptOutputLines()` 摘最大非零 runId，`MainActivity` 轮询注入）——
  起跑即结算的脚本在途表一次都没见过也能补绑上，窗画刚跑完的输出而不是「未开始」。
  兜底补位号 running 恒 false、**不进 `settledRunIds`**（不是"被摘走"，是"还没在途过"）。

**守卫**：`LogWindowStateTest` 5 条（兜底补绑 / 已绑过时行摘不顶掉 keep / 引擎外行号不进补位 /
兜底补位号不假充在途且换绑 / 未绑无补位落空态）+ `LogWindowControllerTest` 3 条（结算后
静默早退零 toast / 结算前仍问宿主 / 换绑不记结算）。**口径**：见
[`design-decisions.md`](../design-decisions.md) 第 83 项。**边界**：CI 双工作流绿
（run 38687279767/38687279961；重跑路径修复后 38689478444/38689478505 亦绿）。
**设备冒烟**：装 432bb36 真形态 APK，demo 跑完窗口第一颗钮 `content-desc="重新执行"`
（图标正确从暂停切成重跑）；暂停/继续态与重跑命中的完整链路待用户真机回执
（demo 太快捕不到在途态，需一条长脚本）。

### 2026-10-15 —— 「脚本执行完不要自动清理输出」：悬浮窗结算不解绑（用户令）

**用户令**：脚本执行完**不要**自动清掉输出（日志管理页的脚本输出列表与详情不受影响 ——
那两处是持久落盘，本来就一直在）。

**病**：`LogWindowState.bind` 在 run 离开在途表时把 `boundRunId` 置 null —— 执行一结算，
悬浮窗立刻切回「本次执行未开始」空态，刚跑完的日志在用户眼前被**自动清掉**。在途表是
"正在跑的"这一句，它不含已结算 run 是**事实**，不是**信号** —— 结算去解绑是把
**执行完成**当成了**不存在**。

**药（纯状态层 + 内容层，JVM 可测；无协议面改动）**：
- `bind` 改为**结算不解绑**：同归属在途 run 缺失时保留既有绑定；只有「从开窗起一次都没
  绑上过」（启动失败/门禁拒/起跑即被停）才落空态 —— 失败 toast 已说原因、窗留空态手动关
  （原有语义一字不动）。输出行照旧按绑定 run 过滤（`visible`），窗口保持画刚跑完的那批。
- 状态新增 `running`（绑定 run 此刻在不在途），据此三处诚实：
  `titleText` 结算后缀「· 已结束」；暂停钮 `enabled = running`（跑完了不可暂停，
  点不动也不弹错）；空行区在「已结算且没输出」时改画「本次执行没有输出（已结束）」
  并指路 日志管理 → 脚本输出（内存环 2000 行理论可挤掉本次行，落盘 `ScriptLogStore`
  只追加不会 —— 不把"读不到"说成"没发生"）。
- `ui/detekt-baseline.xml` 随 `WindowIconButton` 加 `enabled` 参数重生成。

**守卫**：`LogWindowStateTest` 三条 —— 结算后保持绑定 + 输出照常可见 + 标题如实缀「已结束」+
已在途的 keep 再出现仍绑回、结算后同归属新 run 换绑到新那条、从没绑上过（启动失败）
仍空态不缀。

**口径**：见 [`design-decisions.md`](../design-decisions.md) 第 82 项。**边界**：CI 双工作流绿
（run 38645518248/38645518135）。**设备冒烟（06:30 装 `11fd5d7` 真形态 APK）**：坐标序列
（项目页 `540 490` → `main.js` 行尾 ▶ `855 662`）跑完 demo —— `script-logs/index.jsonl` 新增
`{"run":7,…}`、`7.log` 五条 demo 行齐全，pid 全程不变（3888）、logcat 无 FATAL/`cannot be saved`；
结算后窗口保持绑定那条路（绑定 run 离开在途表后轮询继续 `bind(empty)` → keep 保留 run 7）在
进程内跑过不崩。窗口内容（标题「· 已结束」/ 行区照常画）属呈现面，由 JVM 测试钉住、真机侧不读屏。

### 2026-10-15 —— 「日志管理→脚本输出→点一行就闪退」：`LoadState` 进不了 saveable 注册表

**用户报**：日志管理 → 脚本输出，选个日志一点就**闪退**。

**根因（设备实测拿到完整栈）**：`ScriptLogDetail` 把详情三态 `load`（`LoadState`）与行
`lines` 放进 `rememberSaveable` —— 而 `rememberSaveable` 会走
`DisposableSaveableStateRegistry.canBeSavedToBundle` 的可接受类白名单
（`Serializable`/`Parcelable`/`String`/`SparseArray`/`Binder`/`Size`/`SizeF`）。
`LoadState` 的三态是 `data object`/`data class`（`NotLoaded`/`Loaded` 是单例对象、
`Failed` 是数据类），**一个都不在白名单里** → 首帧 `requireCanBeSaved` 直接抛：

```
java.lang.IllegalArgumentException: MutableState containing NotLoaded cannot be saved
using the current SaveableStateRegistry
  at androidx.compose.runtime.saveable.RememberSaveableKt.requireCanBeSaved(RememberSaveable.kt:242)
```

异常冒到进程 → 点一行必闪退（用户报的那一下）。**第一版只改了 `lines`**
（`List<String>` 本体是 `Serializable`、空 List 也过，但 `String` 的 `CharSequence`
匿名实现与 `List.subList` 都不是 —— 行形状稍一变就落进同一条），设备复现证明**真正的
首个抛点在 `load`**。

**药**：两个都改 `remember`（详情是**屏内局部现值**，返回即弃，不跨配置存活 ——
配置重建重新拉一次，成本只是一次本地文件读）。`selectedRunId`（`Long?`）留在
`rememberSaveable`：`Long` 是 `Serializable`，那条不在白名单之外。

**设备验证**：修前 APK 用坐标序列（管理 tab → 日志管理 → 脚本输出 pill → 第一行）
必现 FATAL EXCEPTION；修后同一序列 pid 不变、logcat 无 FATAL/`cannot be saved`。

**教训**：`rememberSaveable` 的失败是**首帧即抛**（注册那一刻就校验现值），
不是"配置切换时才炸" —— 因此这类崩溃在真机上是"点开就死"，在 JVM 测试里看不见
（没有真注册表）。凡放进 `rememberSaveable` 的东西都要能回答"它是白名单里的哪一类"。

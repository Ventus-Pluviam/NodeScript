### 2026-10-28 —— 依赖页第十四批：**ManagementTransition 稳态剥壳（顶层裸直绘）**

用户口径原文：「**翻动起来还是很卡啊，认真优化好不好。翻起来列表一顿一顿的**」。第十三批后
真机（engine-native 真形态 APK）依旧卡 —— 而第十三批的 premise 已在上面被证伪，卡顿与轮询
发布无关，纯渲染侧。

**排查逐层排除**：轮询不发布状态（`pollWhile` 只写局部 var，证伪标注见上一批）；`snapshot()`
整趟 `Dispatchers.IO`（2026-10-17 已修，不掐主线程）；行单元静态（Text×3 + Glyph 常量化 +
两粒无动画 pressable）；contentType/key 正确；顶层 `graphicsLayer`/`alpha` 恒等值下 Compose 1.7
不建离屏层。**剩下与首页（pager 里那份，用户说不卡）唯一的渲染路径差异**：依赖页是
`ManagementTransition` 顶层 —— 稳态也由 `alpha + graphicsLayer + Box.clip(全屏圆角)` 三层包着，
`Modifier.clip` 那层**每帧都给整屏滚动内容重做一次圆角裁剪路径**（非矩形 clip 在 HWUI 走
stencil/clip layer，低端 GPU 上正是「一顿一顿」的经典来源），首页没有任何一层。

**改法**：顶层加 `settled` 判据（`progress == 1 && dismiss == 0 && 无手势 && innerTranslationX == 0`）：
稳态走**裸直绘** —— `Box { content }`，三层包装一个不留（圆角裁剪在稳态本来就不可见：
顶层铺满全屏，物理屏幕自己裁四角；裁剪只在窗口缩小的动画期间有意义）。动画/手势一开始
判据即破、包装挂回，同一帧快照内完成，不闪。`claimPointerHits`（挡触穿）是功能不是动画，
两路都留。

**诚实的边界**：若真机上这刀仍不解决，剩下的结构性差异就只有行物理（几百行一帧涌进视口的
排版成本）与设备档次 —— 那需要真机二分（收起态滑 vs 展开态滑），用户已拒绝二分改走直接修。

### 2026-10-28 —— 依赖页第十三批：**Glyph 坐标提成常量（绘制期零分配）+ 状态「没变就不换引用」短路（轮询期不再整屏陪重组）**

**用户口径原文**：「**依赖列表展开时，滑动特别卡顿**」。

第十二批（10-18）已经去过一轮白扔（派生属性算一次、`@Immutable`、contentType 分开、
行内胶囊不带动画、Glyph 的 Path/Stroke 池子）。这批接着去**剩在热路径上、上批没点名**的两处
（老规矩：本机测不了帧率，禁 Gradle / 禁设备 / 禁 adb 截图读屏 —— 逐条指名道姓地去掉浪费，
不把「去掉了浪费」讲成「已经不卡了」）：

**一、Glyph 绘制 lambda 每帧仍在分配（第二刀）**。10-18 那批的 `GlyphScratch` 池子只覆盖了
`Path` 与 `Stroke`，坐标那一路还漏着：`path(0.19f to 0.36f, …)` 的 **vararg 数组、`Pair` 与
装箱 `Float` 是在调用点现造的** —— 而 `when (kind)` 整段每帧重跑一遍，于是每个可见字形每帧
仍要造十几个小对象。展开的依赖列表一行一颗 ⟳，滚动时就是**每帧上百个** —— GC 是「一段时间
里攒出来的一次停顿」，帧率读屏看到的就是一阵一阵的卡。改法：**84 处 `path(...)` 调用点的坐标
整体提成文件级常量**（`P_<字形>_<笔名>`，`Array<out Pair<Float, Float>>`，类加载时建一次），
`path()` 签名从 `vararg Pair` 改为收这份常量；数值逐字相同、字形几何一条未动，绘制期零分配。

**二、状态「没变就不换引用」（第二刀）**。`NpmState.of` 无条件从快照重建、`pollInstallEvents`
无条件 `copy` —— 而 `npmSnapshot()` 每次回读都造一份**内容相同**的快照（量尺寸那趟走完
node_modules，数字没动）。LazyColumn 的 item lambda 捕获的是 state **引用**，换一份等值的也是
换 —— 安装轮询（每 400ms 一 tick）进行中，~~**展开的整屏可见行每 tick 重组合一次**~~（~~2026-10-28 第十四批复核证伪：`pollWhile` 的循环只写局部变量，`npmState =` 只在轮询结束发生一次，轮询期间页面**从不**重组 —— 本次短路修的是一段不存在的开销，保留只因其无害~~），滑到一半
被打断正是「展开时滑动特别卡」的来路之一。两处短路：

- `NpmState.of`：`snapshot == previous.snapshot`（data class 内容判等）且无失败态、无操作账
  （`opError`/`opNotice` 为 null）→ **原样复用 previous**。两个排除项各有各的理由：
  `LoadState.Failed` 只改 `load` 不动快照，短路会把「读取失败」这句错话留在日志框里；
  `opNotice` 的 KDoc 本来就写着「**现取即清**」，重建那份把它归 null 是这句注释原本答应的行为。
- `pollInstallEvents`：事件游标没推进（`batch.lastSeq == since`）且阶段没变（folded 相等）→
  **原样返回同一份**，不 `copy` 等值实例。

三条新测试钉这三条（`NpmStateTest` 两条、`NpmInstallOpsTest` 一条），全部用 `===` 断**引用**
而不是值 —— `copy` 出来的同值对象救不了重组，只有原样复用才救得了。

**没动、也说明白的**：第十二批第八条那个「为什么首页不卡」的待测数依旧开放（依赖条目量级 /
控制台页与日志管理页是否也卡 / `ManagementTransition` 那两层全屏 `graphicsLayer`）—— 这批没
再往那两层上猜。安装轮询期间**事件真在推进**时的重组（阶段条前进）是合理成本，没为了省重组
把阶段条挪出状态 —— 那是另一笔账。

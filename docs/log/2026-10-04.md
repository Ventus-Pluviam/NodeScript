### 2026-10-04 —— 批 37：菜单圆角精确到12dp，修复主题切换死区及多处UI细节

用户口径：「控件样式颜色，圆角幅度全部抄tg的」；「上面让你改的能抄tg就抄tg」。

**圆角与间距**
- 菜单容器圆角经重新测量（popup_fixed_alert4.9.png 实测 ≈11.90/11.90/11.93/11.88 dp，四档密度均在 11.88–11.93 dp 之间），调整为 **12.dp**（之前记为 11.dp）。
- 菜单项按压圆角同样为 12.dp：三条代码路径——`ItemOptions.setupSelectors`（传 12）、`ActionBarPopupWindow.setupRadialSelectors`（传 6）、`ActionBarMenuSubItem.updateSelectorBackground`（**不传**，仅用两个 boolean 判断首/末项）—— 实际走第三条（`popupLayout.updateRadialSelectors()`），字段保持默认 `selectorRad = 12`（`ActionBarMenuSubItem.java:47`），两条旁证均指向 12。
- 纵向内边距 8.dp 由 M3 `DropdownMenuVerticalPadding` 自带，横向由 [MenuSidePadding] 补足；去除之前尝试用负 padding 抵消 M3 额外 8.dp 的做法（实际上会把纵向压到 0）。
- 分组间隙高度 8.dp 来自 `ItemOptions.addGap()`（`createLinear(MATCH_PARENT,8)`），与 `ActionBarMenuItem.addGap(int)`（高 6.dp、标记 `object_tag` 以触发后一项上圆角）不同，故保留 8.dp。

**底面板与其他组件**
- 底部操作面板圆角约 **24.dp**（`sheet_shadow_round.9.png` 实测 ≈23.85/22.60/24.32/23.93 dp），非 M3 默认 28.dp。
- `ScrollToTopButton` 无直接 TG 对照，参考 `ChatActivityBlurredRoundButton` 规格：44.dp 圆、图标半透明、背景颜色、按下遮罩、状态切换时长 320ms、`EaseOutQuint`。
- `SelectionTick` 并非 TG 的 `CheckBox2(21)`：本仓使用 52.dp 圆形（勾选框填充色 `#5EC245`、勾色白），TG 为 21.dp 方形坐标在 avatar 左下角、外补 42.dp 顶部 padding；仅复刻「实心绿圆 + 勾」的配色与形态。
- `MenuAction.tone` 缺省由 `StatusTone.LINK` 改为 `StatusTone.NEUTRAL` —— 菜单项默认走正文色，仅带后果项（如删除）使用危险色，这是行为上的改动。

**交互与反馈**
- 菜单容器采用 1.dp 半透明描边模拟 9-patch 投影（实测边宽 ≈8.dp、峰值 alpha 33/255），不用 M3 `shadowElevation`。
- 菜单项按压反馈为整块纯色覆盖（`dialogButtonSelector`），而 TG 采用圆角遮罩的 ripple（`RippleRadMaskDrawable`）；此处保留纯色覆盖为文档化偏差，以保持按压色与圆角精准对齐。
- 主题切换死区：`ThemeMode.next()` 现在接受实际明暗参数 `isDark`，冷启 `SYSTEM` 档不再死 tap，用户一切换即进入 LIGHT/DARK 两态对翻。

**编译通过性**
- 补充 `Menus.kt` 中遗漏的 `import androidx.compose.material3.MaterialTheme`（用于 `ActionBottomSheet`、`CopyNotice`）。
- 补充 `ProjectScreen.kt` 中遗漏的 `import androidx.compose.animation.slideInVertically` 与 `slideOutVertically`（用于删除动画）。

（以上条目对应 `ui/src/main/kotlin/com/autoscript/ui/components/Menus.kt`、`ui/src/main/kotlin/com/autoscript/ui/screens/ProjectScreen.kt`、`ui/src/main/kotlin/com/autoscript/ui/theme/Theme.kt` 等文件。）

### 2026-10-04 —— 批 36 勘误：底栏高亮块的底色被 blend 成了灰（用户实测点名）

用户口径：「底栏的背景动效不是淡蓝色的吗，不是灰色的，色号去 tg 源码参考」—— 说的是
**选中格背后那块**，批 36 里我把它写错了。

**错在哪**（对着 `GlassTabView.dispatchDraw` 逐字读）：
```
paintCounterBackground.setColor(Theme.multAlpha(colorSelected, 0.09f * alpha));
```
`Theme.multAlpha(color, m)` = `ColorUtils.setAlphaComponent(color, (int)(Color.alpha(color) * m))`
—— **只改 alpha 通道，一个色相都不动**。也就是说那块底色的**色相恒为 `colorSelected`
（浅色 `0xFF1A91E6` 纯蓝）**，随选中因子变的只有它的**透明度**。

我写成了 `lerp(palette.tabSelected, palette.tabUnselected, f).copy(alpha = 0.09f * f)`
—— 那让 f=0.5 时底色变成 `0xFF1A91E6` 与 `0xFF1A1D21`（近黑）的中点，即**一坨灰**
（≈`0xFF1A5768` 量级的暗青灰）。淡入途中先看见灰、再慢慢变蓝，正是用户看到的现象。
**同一个错误在文字/图标上没有**：那两条 `updateColors` 的 blend 是 TG 真有的
（`blendARGB(colorDefault, colorSelected, factor)`），照抄没错；错的只有高亮块这一处
——我把"颜色 blend"的模式套到了"透明度 blend"的地方。

**同批修的第二处（同一句话里的"色号"）**：透明度那一路 TG 是**过了两遍**
DECELERATE 的 —— `factor` 本身已是缓动值（`FactorAnimator` 把插值器交给
`ValueAnimator.setInterpolator`），而 `dispatchDraw` 又拿它喂了一次
`AnimatorUtils.DECELERATE_INTERPOLATOR.getInterpolation`。本仓原先是线性的 `0.09f * f`，
现改为 `0.09f * (1 - (1-f)²)`，与 TG 的实际曲线对齐。

**如实收窄**：这只解释"淡入途中发灰"，**不解释"看着比 TG 灰"**。深色主题下本仓的选中蓝
是 `0xFF229AF0`（night 回退到 `chat_messagePanelSend`，`night.attheme` 实测值），比浅色
的 `0xFF1A91E6` 亮一档 —— 但深色下**未选中**色是纯白、`0.09` 的蓝底在白字白图标之间
本来就存在感低。若真机看着仍偏灰，下一个嫌疑是**胶囊底**（本仓用 `surface` 顶
`glass_targetMainTabs`：浅色白对白 ✓、深色 `#232326` vs TG 的 `#232324` 差 2），
以及**本仓没做 blur**（TG 那块是 `BlurredBackgroundDrawable`，`solveSrcColor` 反解
源色，本仓是实心 `surface` + `shadow`）。两者都是"看着不一样"的真来源，但都不是
"色号抄错"，本批不动、如实登记。

**顺带把取色链写进 KDoc**（这一处连错两次的根因是"TG 的选中蓝到底是哪个数"没写在代码旁）：
`Theme.kt` 的 `tabUnselected` / `tabSelected` 两条 KDoc 现在写明**两套 attheme 都没设这三个键**
（`day.attheme` 与 `night.attheme` 里 `glass_tab*` 零命中）、各自的回退链落点
（浅色 → `ThemeColors.java` 默认值；深色 → `windowBackgroundWhiteBlackText` / `chat_messagePanelSend`），
并点明"别把浅色的值往深色里搬"。**这一条是上一批真踩到的**：批 36 我一度想直接抄
`ThemeColors.java` 的 `0xFF1a91e6`，那会让深色主题偏暗。

**验证**：`:ui:testDebugUnitTest` 绿（纯 JVM，未编 native、未出 APK —— 用户口径
「不要在本地编译」）。**无真机验证**：这块底色的观感只能上手看。

### 2026-10-04 —— 批 36：底栏整条按 TG 重做（不等宽分格 / 三键各自 blend / 删掉自加的按压态）（分支 `electric-crocodile`）

用户口径：「底栏是四个选项(项目，任务，管理设置)，出去错误底栏相关代码。page 横滑不允许
切页。是要复刻 tg 的前端代码，tg 没有你也别加啊」。

**先如实回报两条已经成立的事**（本轮没动）：

- **底栏本来就是四格**：`MainActivity.Tab` 恒为 `HOME("项目") / TASKS("任务") /
  CONSOLE("管理") / SETTINGS("设置")`，全仓只有 `Chrome.kt` 的 `TabBar` 一处底栏实现，
  没有第二份。
- **横滑本来就不切页**：`HorizontalPager(userScrollEnabled = false)`（`MainActivity.kt`），
  批 25 起就禁了 —— 切页只走页签点按的 `animateScrollToPage`。本批未改这一处。

于是「除去错误底栏相关代码」落在**那条代码本身抄错/自加的地方**（用户在我给的四个选项里
选了「整条按 TG 重做」）。逐条对着 TG 源码读出来的错：

**读 TG 的哪一处**（逐条有出处）：`MainTabsLayout.java`（`onMeasure` 的宽度分配、长按拖选、
容器缩放）、`Components/glass/GlassTabView.java`（`dispatchDraw` 的选中块、`updateColors`
的两条 blend、`setSelected` 的字重、`createMainTab` 的图标/文字摆位）、`MainTabsActivity.java`
（胶囊几何与 `setOnClickListener`）、`ActionBar/ThemeColors.java` + `day.attheme` /
`night.attheme`（`glass_tab*` 三键的取值与回退链）。

**改掉的六处（都是"本仓自己加的"或"抄错了的"）**：

1. **宽度分配**：原 `Modifier.weight(1f)` 四等分，而 KDoc 里写着「按文字宽自适应……
   不走 weight 均分」——**注释与代码互相打脸**。现在照 `MainTabsLayout.onMeasure` 实现：
   三趟试排（`PASS_TEXT_SIZES_DP = {12,12,10}` × `PASS_PADDINGS_DP = {16,8,4}`）、
   `maxTabTextWidthIfEq` 之外的宽格 `weight = 0` 不参与拉伸、两端夹逼
   （超上限等比压 / 不足 `min(dp(320), max)` 按 weight 分差额）、逐格 `round` 后累加左位置。
   **抽成 `state/TabBarMeasure.kt`（纯算术，字体度量从参数注入）**，理由与 `Particles` 同款：
   这条算法一半是能判对错的算术，那一半必须进单测（`TabBarMeasureTest`，10 例）。
2. **几何**：原 `widthIn(max = 344.dp)` + `padding(8.dp)` + 内层 `height(56.dp)`。TG 的三个数
   是 **328 / 8 / 56** —— 344 是 `setMaxWidth(dp(328 + 8*2))` 夹的**外层 View** 宽，背景
   drawable 自己 `setPadding(dp(MARGIN - 0.334f))` 内缩后才画圆角矩形；内容区则是
   `tabHeight = height − padding×2 = 72 − 24 = 48dp`、离胶囊边 4dp。照抄 344 会把胶囊画宽
   16dp。现在：胶囊 `width = 内容宽 + 4×2`（四格短标签时正好 328）、内容高 48dp、
   内边距 4dp。**内容区上限 320dp 与分配下限 `min(dp(320), …)` 互为倒影**，两者相等是 TG
   的原样，不是巧合。
3. **颜色**：`Colors` 里原只有 `tabIdle` 一个键、选中态直接借 `accent`。TG 是**三个键**：
   `glass_tabUnselected`（未选中，图标与文字的公共起点）、`glass_tabSelected`（选中**图标**）、
   `glass_tabSelectedText`（选中**文字**）。逐个查了取值与回退链：day 三个键**都没设** →
   `ThemeColors.java` 默认值 `0xFF1A1D21 / 0xFF1A91E6 / 0xFF0D7FCF`；night 也都没设 →
   `tabUnselected → windowBackgroundWhiteBlackText`（= 白）、`tabSelected`/`tabSelectedText`
   → `chat_messagePanelSend`（= `0xFF229AF0`，两者**同值**）。`tabIdle` 因此改名
   `tabUnselected`（旧值 `0xFF777C7F` / `0xFF8E8E8F` 两档都不是 TG 的数，是估的）。
4. **两条 blend**（`GlassTabView.updateColors`）：图标走 `colorDefault → colorSelected`、
   文字走 `colorDefault → colorSelectedText`，原实现两者共用一个 tint。现在**一个
   `animateFloatAsState` 喂三个颜色**（图标 / 文字 / 高亮块）—— TG 也只有一个
   `isSelectedAnimator`。缓动按 `BoolAnimator(…, DECELERATE_INTERPOLATOR, 320)` 写：
   `ValueAnimator.setInterpolator` 已把 factor 缓动过，所以回调里的 factor 直接用，
   `dispatchDraw` 那句再插一次是恒等操作。
5. **字重**（`setSelected`）：`selected ? TYPEFACE_ROBOTO_EXTRA_BOLD : bold()`。而 TG 的
   `bold()` 是 `Typeface.create(null, 500, false)` 或 `rmedium.ttf` —— **是 Medium 不是
   Bold**；`rextrabold.ttf` 才是 ExtraBold。原实现恒为 `FontWeight.Bold`，两档都不对。
   现在未选中 `Medium(500)` / 选中 `ExtraBold(800)`。**量宽也按 Medium**（TG 的
   `defaultTextPaint` 复制自 `textView.getPaint()`），拿 Bold 量会系统性偏宽。
6. **删掉自加的按压态**：原 `TabBarItem` 有一套「按住整枚向强调色走 0.35 的 blend / 按住
   选中格压暗」+ `collectIsPressedAsState` + `MutableInteractionSource`。**TG 的
   `GlassTabView` 全文零 `setPressed` / 零 ripple / 零 selector**（按住的反馈是
   `clickHelper` 的长按路径，另一件事）。这是"tg 没有的"，按用户口径删掉。
   同时删掉 `TabItem.badge` 字段与 `TabBarItem` 里的 `CountBadge` 分支 —— **TG 的底栏确实
   有计数**（`GlassTabView.setCounter` + `MainTabsActivity` 的 `setCounter("!", true, true)`），
   但本仓唯一调用点恒传 `null`、`MainShell` 的注释写明"刻意不挂徽标"（徽标是"未读"语义，
   与本仓三种账不是一回事）——**留一个永远为 null 的槽位就是那段"错误底栏相关代码"**。
   真要用计数时应按 `setCounter` 的几何（`cx = w/2 + 11dp`、`cy = 10dp`、高 16dp、
   `rOuter 9.333` / `rInner 8`）重做，不是把 `CountBadge` 摆在角上。

**没做的两件（TG 有，但不在"除去错误代码"的范围内，留作后续）**：长按拖选（`checkLongMove`
+ `SpringForce(1).setStiffness(STIFFNESS_MEDIUM).setDampingRatio(DAMPING_RATIO_LOW_BOUNCY)`
+ 容器 `lerp(1, 1.019f, factor)` `EASE_OUT_QUINT` 380ms）与重按回顶
（`TabFragmentDelegate.onParentScrollToTop`）。两者都要动 `MainActivity` 的点击接线，
与本批"只动底栏那条"的边界不同，单独立批。

**验证**：13 个测试任务全绿（`ci.yml` 逐字同一条 `./gradlew`，`-PskipNpmE2E`）+ 全模块
`./gradlew lintDebug` 绿 + `./gradlew :app:assembleDebug` 绿 + 文档链接门 381 条全在。
`:ui` 单测 **81 → 91 例**（新增 `TabBarMeasureTest` 10 例）。**无真机验证**：底栏的观感
（不等宽分格是否顺眼、三键 blend 的中间态、字重换档的跳动）要上手才说得准。

### 2026-10-04 —— 批 35：拆掉下拉刷新 —— 参考项目没有这个手势（分支 `electric-crocodile`）

用户口径：「去除弹性下拉更新，tg没有的不用加」。批 15 给四屏加的下拉刷新是**自己加的**
（不是从 TG 抄来的），批 30（`average-squirrel`）又把它改成自研的 overscroll 弹性形变 ——
两者都不在参考项目里。

**读 TG 的哪一处**（逐条有出处）：

- `RecyclerListView`（TG 全部列表的基类）**只有滚动**，没有任何下拉手势 / overscroll 刷新
  的钩子；`ChatAttachAlertDocumentLayout`（文件选择器，本仓项目页的对应物）的 `listView`
  连刷新项都没有 —— 它读本地目录，**进目录即重读**，`ActionBar` 上只有 `searchItem` 与
  `sortItem`；
- 需要刷新的屏，刷新一律是**显式动作**：`DialogsActivity` 的刷新在 `ActionBar` 那颗
  （`updateColors` 那套）或菜单项里，不在列表上。本仓照此：**刷新入口 = 顶栏那颗
  「刷新」**（项目页收在 ⋮ 菜单里，批 24 就是那么摆的），列表上没有第二条路径。

**落地**：

- `components/Refresh.kt` 的 `RefreshableBox` 去掉 `action` 参数，实现从 M3
  `PullToRefreshBox` 换成裸 `Box` —— **只剩"内容宿主"这一件事，没有手势**。壳保留
  （而不是把四屏拆成裸 `Box`）：四屏的 content lambda 收的是 `BoxScope`，"填满"由调用方
  传的 modifier 决定，留着壳四屏的 body 一行不用动；
- `RefreshAction` **保留** —— 它仍是"点刷新 → 起协程 → 拉数据"的唯一入口（挂起状态持续到
  读口返回、挂起中再触发直接丢弃），四屏顶栏那颗都走它。拆掉的只是**它给手势读的那一面**：
  `isRefreshing` 公开属性、`PullToRefreshBox` / `ExperimentalMaterial3Api` 两个 import；
  内部的 `refreshing` 从 `MutableState<Boolean>` 降成私有 `var`（没有观察者了）；
- **顺带修一处**：`refreshing = true` 从 `launch` **内**第一行提到 `launch` **前**。原实现
  靠 `rememberCoroutineScope()` 落在 `Dispatchers.Main.immediate` 上"立即执行"来兜住
  "连点两下不投两份读" —— 那是派发器的实现细节，不是本类的语义。标志先立后派发，判据才
  跟调度无关（`finally` 清标志那条不变：读口抛了也得能再刷）；
- 项目页 ⋮ 菜单里的「刷新」原先是 `{ scope.launch { refresh.trigger() } }`（多包一层协程 ——
  `trigger` 自己就起协程），顺手改回 `refresh::trigger`，与另三屏顶栏那颗同一个写法。

**影响面**：`ProjectScreen` / `SettingsScreen` / `TaskCenterScreen` / `ConsoleScreen` 四处
调用点去掉 action 参数（`:ui` 内唯一调用面，全仓无其他引用）；三处 KDoc 里「下拉刷新与顶栏
那颗同一个动作」的话删掉，`MainActivity` 里「四个屏各自带着 LazyColumn / 下拉刷新容器」改成
「各自的列表子树」（那句是在讲重组代价，不是讲刷新）。

**验证**：13 个测试任务全绿（`ci.yml` 逐字同一条 `./gradlew`，`-PskipNpmE2E`）+ 全模块
`./gradlew lintDebug` 绿。`:ui` 81 个测试不变（本次没有可 JVM 测的纯逻辑增量 —— 改的是
Compose 容器与手势的有无）。**无真机验证**：拆手势的观感（少了"拉一下"的反馈之后，顶栏那颗
按钮是否够显眼）要上手才说得准。

**与 `average-squirrel` 的冲突（登记，不擅自裁）**：该分支批 30 是「TG 弹性形变下拉刷新」，
与本批口径**相反** —— 且它自己也承认那是自研的（"不用 M3 PullToRefreshBox，走 TG
`RecyclerListView` 同款语义"里那条"同款"是推的，TG 源码里没有这段手势）。该分支的批 26–33
尚未移植到本线；真要移植时，`Refresh.kt` 这一处按本批口径走（删），其余批次逐条另判。

### 2026-10-04 —— 批 34：项目页「一层一层走」—— 目录下钻 / 选择模式 / 底部操作面板（分支 `electric-crocodile`）

用户口径是「参考 tg，交互逻辑要复刻」里**还没接上的那一半**：批 23–25 把项目页的**版式**
（顶栏 / 搜索栏 / 列表行 / FAB / 胶囊底栏）抄到了 TG 的样子，但**点下去什么都不发生** ——
`FileRow` 的 `onClick` 是空回调，`ActionBottomSheet`（批 24 定义好、`Menus.kt` 里躺着）
全仓零调用方，文件夹行点了不会进层。这一批把交互接上。

**读 TG 的哪一处**（逐条有出处，不凭印象）：`ChatAttachAlertDocumentLayout.java`
（文件选择器 —— 本仓项目页在 TG 里的对应物，不是 `DialogsActivity`）：

- **一层只显示一层**：TG 文件选择器有明确的当前目录概念（`getCurrentDir` / 返回键逐层回退），
  不是把整棵树平铺出来。本仓原先的列表是**整棵树平铺**（`files/scripts/` 全量行），
  一个 `lib/helper.js` 和它上面的 `lib/` 目录行并排显示 —— 层级信息只能从 `relPath` 里读。
- **搜索是另一份数据集**：`searchAdapter` 搜的是**全库**（还带"最近"分区），
  `onSearchExpand` 时列表整个换掉、`onSearchCollapse` 时换回来（并 `searchAdapter.search(null)` 清空）。
  **不是**"在当前目录里筛一下" —— 用户敲文件名时找的是"那个文件在哪"，锁在当前层就是答非所问。
- **搜索栏展开时排序项隐藏**（`sortItem.setVisibility(View.GONE)`）：搜索结果不吃排序档。
- **选择模式的入口是长按**（`isEnabled` / 多选勾选那套），勾**占最左那一格**（头像让位），
  顶栏换成"已选 N 项" + 那格开关。本仓的顶栏那颗按钮字形跟着语义走（`‹` 退回 vs `✕` 关闭模式）。

**落地的四件事**：

1. **目录下钻**（`ProjectState.childrenOf`）：`currentFolder` = relPath 的**全路径前缀**
   （含项目名，如 `"demo/"`、`"demo/lib/"`；null = 全库根）。目录行的 `relPath` 本身就是
   合格的前缀，所以"进一层"就是把 `file.relPath` 赋给 `currentFolder` —— 不做字符串拼接。
   顶栏标题换目录名、副标题给完整路径（TG 文件页顶栏那两行）；进了目录才给 `‹`。
   返回键 `‹` 与 `BackHandler` **共用同一条 `goUp()`**（两条路各写一份迟早漂移）。
2. **搜索跨层**（`ProjectState.poolFor`）：搜索时候选集是**整棵树**，否则是当前一层的直接子项。
   从搜索结果点进目录要**同时收起搜索**（否则进了层列表还是全库的搜索结果，等于"点了没反应"
   —— TG 的 `onSearchCollapse` 同款）。空态因此分三句：搜出来的空 / 这层是空的 / 全库是空的
   —— 说成同一句会让人去改搜索词，而问题在根本没文件。
3. **选择模式**（`ProjectState.toggleSelection` / `toggleSelectAll` / `allSelected` / `keyOf`）：
   长按进模式并勾上那一行，点行 = 勾/去勾。**全选的范围是当前可见集**（不是整棵树）——
   把看不见的行也圈进来，后续动作就会动到用户没看到的东西。顶栏那格是**同一个开关**
   （选满了自己变成"取消全选"），FAB 在模式里收起（TG 的 action mode 里没有"新建"这一档）。
   选中态是**整行淡底 + 头像位换成勾**（勾与头像同格同位，行内其余内容一格都不动）。
4. **底部操作面板**（`ActionBottomSheet` 首次接线）：点文件行弹出，大触控目标整行。
   **只放今天真能做的**：复制路径（走既有的 `CopyAction`，控制台同一条）+ 进文件夹（目录行才有）。
   运行 / 重命名 / 删除要宿主侧读口，而 `HostSummary` 目前只有 `createEntry` —— 没有的口
   **不摆成按钮**（摆了就是点了没反应）。这是本批**如实收窄**的地方，不是漏做。

**顺带修的两处**：

- **`ActionBar` 加 `backGlyph`**（缺省 `‹`）：选择模式那颗是**关闭**不是返回
  （按它退的是模式，不是页面），同一个位置画同一个箭头会把两种语义读成一件事。
- **`selected` 存成 List**：`Set` 不在 Bundle 认得的类型里，`rememberSaveable` 的 autoSaver
  存不下它（配置变更时会抛）—— 用 `listSaver` 存 List、回来再收成 Set。

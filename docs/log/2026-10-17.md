### 2026-10-17 —— 依赖页第六批：**「清理未声明依赖」改名「清理依赖」** + 页底三个动作**重新做成三张等宽白卡**（图标在上、文字在下）+ **卡底那句说明下线**

**用户口径原文**：「**清理未声明依赖改名啊，改成清理依赖**」「**样式是图片中这样，3个按键。重新做**」
「**不要加多余的描述啊**」（第三句是在参考图之后补的，指的正是那三格下面那段小字）。

用户要的是短名，说明留在 KDoc 与 `NpmMaintenanceAction` 那边。文档里那条旧口径原地划掉，不删。

**二、样式整条推翻，不是微调。** 第五批那版是：一张 `PanelCard` 里三行 TG 子菜单式选项

### 2026-10-17 —— 依赖页第五批：**「全局为什么没有 node_modules」**、输入框收短右对齐、作用域缺省改全局并入尺寸卡、**维护卡下线换成页底三个 TG 式选项（点击走水波）**

**用户口径原文**：「**全局为什么没有显示node_modules**」「**安装依赖的输入框长度短一点（右对齐），
样式抄一下首页的搜索框**」「**依赖作用域，默认为全局，放进和node_modules和npm缓存同一个列表分组**」
「**去除维护列表，清理依赖，依赖去重，清理缓存弄成3个选项。这3个样式参考tg的，tg源码在/tmp/tg，
点击动效也参考tg的。选项放在最下面**」。

**一、「全局为什么没有 node_modules」是问句，不是改法 —— 查出来的原因在两档作用域口径不一致。**

用户看到的现象：作用域切到「全局」时，尺寸卡里只有「npm 缓存」那一行，`node_modules` 那行**整个不见了**。
原因是**同一个物理事实（这棵 node_modules 还没建）在两档作用域上画出了两种界面**：

- **全局那条**（`InstallCoordinator.globalSnapshot`）此前判 `Files.isDirectory`，不存在时给
  `storage = null`，界面按本页那条「没量到就不画」的纪律把整行藏了；
- **项目那条**永远不会 null —— `storage()` 给每个项目都构造一份 `NodeModulesStats`，
  目录不存在时 `totalBytes` 就是 0，界面照样画一行「node_modules 0 B」。

修法在**宿主侧一行**：全局那条不再给 `null`（`totalBytes` 为 0 时如实说 0 B），与项目同口径。
界面一行没动 —— 「没量到 ≠ 0 字节」那条纪律本身是对的，错的是它在这两档上**不是同一个意思**。
**这条口径变更同时是第 21 条的前提**：缺省作用域正要改成全局，那时一进这一页就少一行，读起来像坏了。

**二、「安装依赖」输入框收窄 + 右对齐，版式与首页搜索框**合成一份**。**

用户口径「样式抄一下首页的搜索框」。原来是**再抄一份**（`InstallField`）还是**共用一份**的选择题 ——
`ProjectScreen.CapsuleInputField` 的 KDoc 自己写着「用户要的是"一样"，两份拷贝只能靠"记得同步改两处"
维持一样 —— 共用之后"一样"是结构上的事实」，而这是**第三个**使用点（搜索框 / 新建对话框 / 安装行），
它住在另一个**屏**里、`private` 到不了 `screens` 之外。于是搬进
`ui/src/main/kotlin/com/autoscript/ui/components/Inputs.kt`（**搬的是位置，版式那几个数一个没动**），
末尾补两个新参数 `enabled` / `onSubmit`（仓规：新参数排在参数表末尾）。三个使用点此后共用同一份。

右对齐是**算出来的**，不是拿 `Spacer(width)` 顶出来的：输入框改成**定宽** `168.dp` 之后，左边多出来的
空间全归标签自己的 `weight(1f)` —— 于是「标签贴左、框与执行钮贴右」在窄屏上会**自动让位**
（标签被压窄），写死的 `Spacer` 则会把整行顶出屏幕。提示语从「axios 或 axios@1.7.0」收成
**「如 axios@1.7.0」**（框窄了，长的放不下）。

**三、依赖作用域缺省改「全局」+ 与两行尺寸并成一张卡。**

缺省回落**三档、顺序不能换**：用户上次选的（还在）→ 快照里那条全局 → 第一条项目。中间那档不是凑数 ——
全局那一条是**宿主拼上去的**（`globalSnapshot`），测试替身与非本宿主的快照里可以没有它，那时凭空选中
空串就是选了一个清单里不存在的条目（屏幕上"作用域写着全局、下面什么也没有"）。
选中态本身那条纪律一字未动：**刷新不许把用户正在看的那个作用域换掉**。

并卡（`ScopeCard` = 依赖作用域 + node_modules + npm 缓存）不是排版偏好：三行回答的是同一个问题
（"这一屏在管哪一棵 node_modules、它有多大"），分成两张卡时要跨一条灰缝才读得出来。
依赖列表的卡头与空态措辞一并**跟着作用域改口**（`NpmState.scopeIsGlobal`）—— 缺省是全局之后再写死
"项目依赖"，就是**天天在说错话**（全局那棵 node_modules 不属于任何项目）。

**四、维护卡整张下线，三个动作变成页底的三个 TG 子菜单式选项。**

「清理未声明依赖」（`prune`）/「依赖去重」（`dedupe` + 提升到全局）/「清理缓存」（按各作用域 lock 的
并集回收）。第三颗是**回家**的：它在本日早些时候随「去除 npm 缓存下面的字，去掉右边的清理按钮」
下线过一次（当时本页没有入口，宿主与 `reclaimNpmCacheOp` 都还在也还测着），本批按用户口径做成第三个
选项，**代价条款随之撤销**。

样式与动效都取自 TG 源码（`/tmp/tg`）：

- **行**：`ActionBarMenuSubItem` 的几何 —— 高 48dp、左起 18dp、24dp 前置图标 + 16sp 正文。
  与设置页那条 `SettingsCellRow` **不复用**：那一条是"设置项"的读法（28dp 彩色圆底图标块 +
  行尾值），本行是"动作"（灰线图标 + 一个「进行中…」的尾巴 + 另一种按压动效）。
- **点击动效**：TG 的行按下是 `Theme.getSelectorDrawable(false)` → `createSelectorDrawable(color,
  RIPPLE_MASK_ALL)` —— 掩码是**整个格子**的 `RippleDrawable`，圆心跟触点、半径长到铺满整行。
  本仓此前的 `pressable` 是"整块纯色覆盖"（那是**本仓的选择**：小行高、快速滑动下更跟手，
  见 `Interaction.kt` 的 KDoc；说"TG 的行是整行变暗"准确讲是老 API 上 `SelectorDrawable`
  掩码档的样子）。本批新增 `Modifier.pressableRipple`（`components/Interaction.kt`，走 M3 的
  `ripple(bounded = true, color)`，与 TG 那条 `RippleDrawable` 是同一个东西），**只给这三个选项行用**，
  `pressable` 仍是全仓缺省。
- **位置**：整页最下面（用户口径），**在日志大框之后** —— 动作都落在"当前作用域那棵树"上，
  而日志框正是看那棵树刚才发生了什么的地方：按下去、往上看结果。

禁用判据两条同源（`canInstall` / `canReclaimCache`）：安装、维护、回收三者互斥（`globalSession`），
只禁被按下的那一颗会让另两颗看起来还能按、按下去是排队。进行中的那一颗行尾写「进行中…」——
比"这一颗变蓝"清楚（整行染色会与按下的水波混在一起）。
卡片下面那句小字留着：「依赖去重」**顺带把依赖装一份到全局**是用户按下去之前有权知道的事
（它改的是落盘那棵树，影响面超出当前作用域）；措辞跟着作用域走，作用域本来就是全局时明说这一步跳过。

**五、验证与守卫。** 宿主侧 `InstallCoordinatorTest` 那条断言从"没建时 `storage` 是 null"翻成
"**是 0 而不是不画**"，并补上"同一个物理事实两档作用域同款"的对照；`:ui` 侧 `NpmStateTest` 改 1 条
（缺省那条断言连同它写的理由一起翻）、补 2 条（三档回落、`scopeIsGlobal` 认空串且没读到时不冒充）。
**四处变异全部当场变红**：全局 `storage` 改回 `null`、缺省改回第一条、去掉中间那档回落、
`scopeIsGlobal` 对 null 返回 true。三模块 detekt 干净（`ui/detekt-baseline.xml` 外科式改 8 行：
2 条签名重写 + 6 条删/增），文档链接门与冻结面门通过。叙事见 [`design-decisions.md`](../design-decisions.md) 第 97、98 项。

### 2026-10-17 —— 依赖页第四批：**去掉两颗旗标（离线优先转写死缺省）**、清理改名「清理未声明依赖」、**去重并提升到全局**、按 lock 重装下线、**每行重装 ⟳ + 尺寸**

**用户口径原文**：「**去掉开发依赖，和离线优先。默认开启离线优先。**」「**清理多余包名字改成清理
未声明依赖**」「**依赖去重执行后让它把依赖自动放进全局作用域中**」「**去除按lock重装。**」
「**在依赖列表里，加一个重装的图标按钮，依赖列表显示一下各个依赖占用的空间大小。**」；
两处含糊当场追问后用户裁定：去重那颗按钮的行为取「**去重后再装一份到全局**」，
重装图标「**每一行一个（和「卸载」并排）**」。

**一、两颗旗标整行下线**（`-D（开发依赖）` 与 `离线优先`）。两条下线的理由**不是一回事**，
账要分开记：

- 「离线优先」**不是删能力**，是把 `--prefer-offline` 变成**写死的缺省**
  （`NpmInstallOps.INSTALL_FLAGS`）。做成"默认点亮、可以关掉"的旗标等于承认还有另一种装法，
  而 §10 的离线能力全建在 npm 缓存上 —— 先查缓存没有理由关。同理**不留**一句
  「离线优先已开启」去填那块空位：那是把"没有开关"说成"有个开关正开着"。
- `-D` 是**语义**下线：它装的是"开发这个包的人才要"的那一档，而这一屏回答的是
  "这个脚本跑起来要什么"。`NpmState.installDev` / `installOffline` 两个字段一并摘掉
  （`canInstall` 的判据里本来就没它俩）。
- **代价如实记**：想装 devDependencies 只剩控制台 `npm install -D <pkg>` 一条路
  （那条路一直在，白名单没动）。

**二、「清理多余包」→「清理未声明依赖」**（只改文案，判据一字未动）：`prune` 删的就是
lockfile 里没有声明的那些 —— 旧名字把一件**有判据**的事说成了主观判断（"多余"由谁定）。

**三、「依赖去重」变成「去重 + 提升到全局」**（用户裁定「去重后再装一份到全局」）。这条是
本批唯一跨三层的新能力，四段账：

- **`PackageManagerFacade.promoteToGlobal(projectId)`**（`:domain` 新读口，冻结清单同步 +1）。
  取的是项目 `package.json` **声明的**依赖（`dependencies` + `devDependencies`），
  **不是 lock 的闭包** —— 闭包是几百个包，每次点这颗按钮把整棵树抄一遍全局不合理；
  **带声明的范围**（`axios@^1.7.0`）而不是锁定版本，全局那份跟着项目走小版本、两边不分家。
  目标固定 `NpmTargetScope.GLOBAL`。
- **两种"没有"两句话**：没 `package.json` → `ERR_FILE_NOT_FOUND`（缺的是清单本身）；
  有清单但两个段都空 → `ERR_NOT_FOUND`（清单在、里面没东西）。原样透传到界面。
- **走的是与控制台逐字相同的那条重操作路**：同一次 `packageSpecsIn` 取包说明符 →
  同一次 `crossCheckRegistry` 多镜像交叉校验 → 同一次 `enqueueHeavy`（磁盘预检 / 项目锁 /
  全局会话 / journal 事务）。门禁强度不取决于用户是从哪个界面按下去的（与安装行同一条纪律）。
  ECHO 行落在**全局**那份控制台里 —— 这次安装真跑在全局，把回显记到项目那份等于在一个
  作用域的账本上记另一棵树发生的事。
- **薄薄一层 `declareSpecs` + `promotePlanOf`**：前者（`NpmScriptResolver.declaredSpecs`）
  读清单两个段、同名只算一次、**按名字排序**（否则每次提升的 argv 顺序都可能不一样，没法对拍）；
  后者（新文件 `PromotePlan.kt`）把上面那两句话与 argv 拼装收在一处。
  返回值是 `(specs, args)` 两件 —— 让调用方从 argv 里往回剥（`drop(1).dropLast(1)`）等于
  把这一层的形状泄漏出去。

**四、那两颗按钮的编排刻意分开**。「依赖去重」**不走** `<枚举> -> runNpmMaintenanceOp` 那条
通用路，而是自己一条 `runDedupeAndPromoteOp`：它做的是**两件事、落在两个作用域上**
（先去重当前这棵，再把声明的依赖装一份到 `files/scripts/node_modules`），硬塞进
`(NpmMaintenanceAction) -> Unit` 就得让 `onMaintenance` 去猜"这次 dedupe 是不是还要顺带提升"。
**两段各自的成败分开说**，三条刻意见那个函数的 KDoc：前段失败 → 整颗报失败**且不做后段**
（依赖树还乱着就往外提升 = 把半成品抄成全局的基准）；前段成功、后段失败 → **两个都给**
（`opNotice` 说去重已入队、`opError` 说提升为什么失败）—— 只报失败会让用户以为整颗按钮什么
也没干，于是又点一次、去重被重跑一遍；作用域本来就是全局时**不提升**，回执里**明说跳过了**
（否则用户以为"提升"那半截悄悄失败了）。

**五、「按 lock 重装」整颗下线**（用户口径「去除按lock重装」）。理由是它的门禁解释成本高、
收益只有一种场景（lock 与 node_modules 漂了）。**代价如实记**：`NpmMaintenanceAction.CI`
在本页没有入口了 —— 宿主那条验签路径、`runNpmMaintenanceOp` 的通用路与它们的单测**都还在**
（枚举三个取值一个没少），控制台照样敲得动，想放回来随时可以。维护卡由此从三颗减到两颗。

**六、每行一颗重装 ⟳ + 每行尺寸**。

- **⟳ 是画出来的**（新字形 `GlyphKind.REFRESH`，本仓不引图标依赖）：开口圆环 40°→320°
  + 弧端一支箭头。开口与箭头**两样都要** —— 只画整圆会被读成"环形进度"或"齿轮"，
  只画半圈认不出方向。箭头那三点不是随手挑的（KDoc 里记了来历：弧的终点坐标由半径与
  320° 算出，两支倒刺沿**反切线**转 ±35°、各退 0.15，"尖朝行进方向、V 口朝后"这句话在

**一、全局依赖落地**（第二批那条「未做」本次做掉，`docs/backlog.md` 同批追记）。
落点 = `files/scripts/node_modules`，编码 = 根层哨兵 `ProjectId.ROOT`（空串）：

- 新增 `:domain` 的 `NpmTargetScope`（`GLOBAL` / `isGlobal` / `label`）—— 作用域的**编码与说法**
  的唯一一份；`label("")` = 「全局」，界面上空串不许显示成空。
- **为什么必须落在 `files/scripts/` 这一层**：用户要的「项目依赖优先」是 Node 自己的行为 ——
  `require` 逐级向上找 `node_modules`，项目目录 `files/scripts/<id>/` 正压在 `files/scripts/`
  底下，全局那份落在这儿，项目自己的**天然更近、天然优先**，一行代码都不用写。换到别处
  （如 `files/npm-global/`）它就不再是任何项目目录的祖先，那条规则要靠 NODE_PATH 去补，
  而 NODE_PATH 只对 CJS `require` 生效、还得改引擎 spawn。
- **换来的**：全局与项目走**同一套寻址** —— `projectRoot(ROOT)` 天然是 `files/scripts/`、

  ① 项目枚举要把 `node_modules`（还有安装暂存 `node_modules.part-*`）排掉 —— 那两个名字

  `NpmProjectLayout.projectIds` / `isReservedDirName`，三个枚举点共用）；
  ② 回收缓存的保留集要把全局那份 lock 算进来 —— 它是项目根下的一个**文件**，按目录扫的循环
  看不见它，漏掉的话"只被全局依赖用着"的包会被当成没人要的删掉，全局那份离线重装当场失效。
- 门禁放宽一处：`NpmConsoleKeys.rejectProjectId` **放行空串**（它从前拒空）。放宽的只是
  "非空"那一条，**防逃逸那一条一字未动**（`resolve("")` 恒等自身，逃不出项目根）；话术里
  「不能为空」半句同批删掉 —— 留着就是话术与判据又漂一次。项目号的**创建**侧照旧拒空

  `files/scripts/node_modules` 还没建）：下拉里得先有这一项，用户才谈得上"往全局装第一包"；

### 2026-10-17 —— 依赖装多了「查看时闪退」（`list` 归一 + 读口落 IO）+ 同一句报错说两遍

**用户口径原文**：「**取消上面位置的报错，留下面就行**」「**还有就是依赖装多了，查看的时候容易闪退**」。

**病一（崩）**：已装清单 `list()` 是把 lockfile v3 的 `packages` 段**逐键**读出来的平铺闭包，
而 lock v3 的键是**安装位置**（`node_modules/c`、`node_modules/a/node_modules/c`…）、
**不是包的身份** —— peer 冲突的典型形态：根上 c@2，a 与 b 各嵌一份 c@1，于是同一份清单里
出现两条 `c@1.0.0`。而依赖管理页用 `items(key = "<name>@<version>")` 铺它，**键重复时 Compose
当场抛**（类 `androidx.compose.ui.layout.LayoutNodeSubcompositionsState`：
`Key "c@1.0.0" was already used. If you are using LazyColumn/Row please make sure you provide a
unique key for each item.`）—— 装得越多，撞上的概率越高，正对用户那句「依赖装多了」。
**药**：`list()` 按 `(name, version)` 归一出**包清单**（页面本来不画路径，两行一模一样的字配
两个「卸载」没有信息量；`npm uninstall` 认的也是名字）。`offlineGap` 不归一：缺口的判据是
integrity，同一 包@版本 的两份落点共用同一个 integrity，归一只会丢信息。

**病二（卡）**：`snapshot()` 那一趟是「全项目目录遍历 + 每项目**两份** lock 解析（`list` 与
`offlineGap` 各解析一遍）+ 每棵 `node_modules` 全树算尺寸 + 缓存目录遍历」，而进这一页、
点刷新、以及安装期间每 400ms 一次的续拉，都是主线程那条协程（`rememberCoroutineScope()` = Main）
**直接 await** 它 —— suspend 只给"可挂起"的许可、**不搬线程**。依赖多时这就是主线程上一次几百
毫秒的阻塞，Android 上表现为 ANR（与今天早些时候那条 `NetworkOnMainThreadException` 同族；
那次只补了"取 packument"那一处，其余读口一并漏着）。
**药**：重读口**整趟落 IO** —— `list` / `offlineGap` / `storage` / `snapshot` / `reclaimCache`
包 `withContext(Dispatchers.IO)`；`nodeModulesBytes` 改成**挂起函数并在自己那一层落 IO**
（两个调用方 `storage()` 与 `enqueueHeavy` 的配额预检都在主线程那条链上，60s TTL 意味着
每分钟重演一次）；控制台轻操作的取数（`npm ls`）同理。这就是本文件既有的写法
（`crossCheckRegistry` / `cacheStorage`），本批只把先前漏的补齐。
**一处不好看但必要**：`storage()` 里 `Files.list(...).use { forEach { } }` 的 `Stream.forEach`
收的是 Java 的 `Consumer`（非内联 lambda），**里面调不了挂起函数** —— 于是先收项目目录名、
再按名字逐个走尺寸那一趟（`for` 循环里才允许挂起）。

**病三（同一句报错说两遍）**：**药** = `NpmState` 新增 `progressFailureShown`
（阶段条**收尾 + 失败 + `detail` 非空**），顶上那条 `opError` 只在它为 false 时画，留着下面那条
（它挨着"这次操作"的上下文）。判据里「`detail` 非空」是必须的：下面画的是「失败：（无详情）」
时若把顶上那条按下去，用户就**看不到失败原因**了 —— **宁可重复，不可失语**。校验拒绝

**回归闸（都已对拍）**：`InstallCoordinatorTest` +3（`list` 归一：5 个安装位置 / 4 个 包@版本 的

`offlineGap` 同一纪律）；`NpmStateTest` +1（三档：跑着中 / 失败带原文 / 失败无详情）。
**对拍一**：把 `InstallCoordinator` 换回 `HEAD` 版、保留新用例 → 3 条全红（归一那条报

宿主 JVM 侧同样是真数。**先判存在**：不存在的路径 `usableSpace` **回 0**，而"项目目录在第一次

`ERR_DISK_FULL`（本次实测：本机 `new File(不存在).getUsableSpace() == 0`，Android 同语义）。

**回归闸**：新增 `FreeSpaceTest` 4 例（存在目录读出真数 / 不存在回 0 / 不存在时退 fallback /

fallback」那例立刻红（`expected: <true> but was: <false>`）。
**如实记一条测不到的**：宿主 JVM 的 `getFileStore` 是好的，所以"Android 那格没实现"这件事在
JVM 上**钉不住** —— 这条修的是设备事实，单测只守得住新读法的正确性，不构成对 Android 的证明。

「**顺带做上**」。

**宿主侧补两个口**（此前一个删除口都没有，呈现层也拿不到绝对路径 —— 它不知道 `filesDir`）：
`HostSummary.deleteEntry(projectId, relPath)`（**文件夹递归整棵**；不存在**抛**，静默成功会把
"删错了对象"与"删掉了"画成同一件事）+ `HostSummary.absolutePathOf(projectId, relPath)`
（**不查存在性** —— 与 `ScriptPaths.scriptFile` 同一条分工"约定只回答应该在哪"，刚删掉的行照样
复制得出它原来在哪）。两个都写成**抽象成员**而不是 `runScriptFile` 那种缺省抛：全仓只有两个实现者
（`AppShellApplication`、`:ui` 的 `FakeHost`），抽象能把"没接线"变成**编译期红**。

`:app` 侧落点全在 `ScriptFileOps`，与既有四口共用同一条 `resolveInProject`（防越界 + 首段与项目名
一致 + 根层单段）：`delete` 多两道闸（目标必须存在；不许是 `files/scripts/` 本身 —— 根层单段判据
理论上已挡，但那条闸挡的是"删掉整个项目库"，值得自己有句话），删目录走 `walk` 逆序 + `deleteIfExists`
（`Files.delete` 对非空目录抛 `DirectoryNotEmptyException`，而"删文件夹"在用户眼里是一个动作）；
`absolutePath` 就是 `resolveInProject(...).toString()`，**不另写一套容错拼法**（拼错的方向是"复制出去的
路径指向另一个文件"，而用户拿它去别处用时不会再有人校验一遍）。`AppShellApplication` 两个 override
与 `createEntry` 同一句口径：只看 `files/scripts/` 落盘、**不依赖壳寄存器**（装配中/失败时删除照常可用）。

**呈现层**：菜单三项 —— 「复制相对路径」（= 原「复制路径」改名，值不动）/「复制绝对路径」
（宿主现取，**失败原文说出来**，不静默复制一条空的）/「删除」（`StatusTone.PROBLEM` 红字，
**点了即删、不弹确认框**）。「进入文件夹」那一项**删掉**了：点目录行本身就是进一层，菜单项与主手势
重复了一件事。选择模式顶栏加一格「删除」（排在「选择全部」**右侧**：破坏性动作不放拇指先够到的位置），
点完**退出选择模式**（行没了，选中集里不能留幽灵键 —— 留着的话顶栏还写"已选 N 项"）。批量目标由新增的
纯函数 `deleteTargets(selected, files)` 算：**剪掉被另一个选中项包含的后代** + **深度降序** ——
搜索态的池子是**整棵树**，父子可以同选，先删父再删子会让子项那一下撞"条目不存在"**假报失败**；
前缀判据靠目录行 relPath 的**尾随 `/`**（`"demo/lib/"` 是 `"demo/lib/a.js"` 的前缀，`"demo/lib"` 不是，
少了这个斜杠 `lib` 会误吃掉 `liba.js`）。它住在**文件顶层而不是 `ProjectState.Companion`**：那是操作语义
（选中 → 要删哪些）而不是同伴对象里"选中集 ↔ 可见集"的读取语义，且那个 companion 已贴到 detekt
`TooManyFunctions` 上限（11）—— 同批 `ScriptFileOps` 也因此在 11 个函数上把 `requireName` 与
`requireProjectName` **合成一个**（判的是同一个东西：这个名字，只是"落盘后是不是项目目录"多一档）。

**代价与已知边界（如实记）**：① **删除不弹确认框**（用户口径）—— 不可撤销、**没有回收站**，
菜单项是红的但误触即永久丢失；② **根层文件夹可删 = 可以一次删掉一整个项目**（用户裁定"允许"）；
③ 删除**不检查在途执行**：引擎已把脚本读进内存，删文件不打断本次执行，下一次投递才是
`ERR_FILE_NOT_FOUND`；④ 编辑器里正开着被删的文件时，「保存」得到的是既有的诚实拒绝
「文件不存在（不新建）」，不另加逻辑。
